# 제작 스튜디오 프런트 구현

2026-10-06. 경로 `/studio`. 기존 Next.js/React/TypeScript 프로젝트에 CSS Modules로 추가했다. 백엔드와 외부 API 계약은 변경하지 않았다.

> 작업실·독립 원본·여러 작품 분리와 삭제/복구 기능은 `docs/studio-workspace-fixes-2026-10-06.md`의 최신 동작을 따른다. 아래 기존 구현 기록에서 저장과 보관함 구조는 해당 문서로 갱신되었다.

## 디자인 기준

사용자가 제공한 로어 기본 Light, 고급 Light/Dark, 작품 개요 Light, 캐릭터 편집 Light, 시작 장면 Light PNG를 사용했다. 저장된 `tmp/figma-studio-phase1.js`, `phase2.js`, `phase4.js`, `figma-studio-ui.js`와 `docs/figma-creator-studio-brief.md`도 참조했다. Figma MCP Starter 한도 이후 사용자가 PNG와 저장된 원본으로 구현하도록 승인했다.

화이트/다크 색상은 공통 토큰을 사용한다. 데스크톱 상단 바는 72px, 자료 탐색기는 260px, 미리보기는 340px다. 캐릭터 화면은 PNG처럼 중앙 편집기와 미디어 패널에 넓은 공간을 사용하고, 테스트 시 미리보기를 열 수 있다. 1150px 이하에서는 미리보기를 필요할 때 열고, 760px 이하에서는 자료/편집/미리보기를 하나씩 표시한다. 캐릭터 미디어는 좁은 화면에서 폼 아래에 배치한다. 입력 글자는 모바일 16px이며 하단 안전 영역을 적용한다. PNG에 모바일 시안은 없어 기존 합의한 계획에 맞춰 구성했다. Noto Sans KR가 없으면 맑은 고딕으로 대체한다.

## 동작

- **작품**: 제목, 공개 소개, 정리 태그, 비공개 세계관/진행 규칙, 초안 공개 범위, 기본 시작 장면 편집. 연결 자료 목록에서 캐릭터/로어/장면으로 이동한다. 수량은 실제 초안 데이터로 계산한다.
- **캐릭터**: 이름, 공개 소개, 비공개 성격/말투, 대사 예시, 역할/관계, 태그 편집. 보관함에서는 독립 원본을, 작품에서는 작품 전용 복사본을 편집한다. 적용 범위는 실제 저장 대상과 일치한다.
- **이미지**: 초상 등록, 표정 이미지 일괄 등록, 표정/장면 용도 선택, 연결 해제. PNG/JPG/WebP, 파일당 8MB 이하, 한 번에 20개 이하를 지원한다. 파일은 브라우저 IndexedDB에, 목록은 초안에 저장한다. 연결 해제된 파일은 브라우저 DB에 남으며 서버 연결 시 정리 정책을 추가해야 한다.
- **시작 장면**: 제목, 비공개 배경, 독자에게 표시되는 도입 대사, 첫 인물, 시작 장소, 초기 상태, 장면별 인물 변형, 언어, 작중/서술 시점 편집. 장면 복제와 해당 장면 테스트 진입을 지원한다.
- **로어**: 제목/분류/폴더/본문/태그, 활성화 방식/키워드, 하나/모두 일치, 우선도, 검색 범위/대상, 부분 일치/대소문자, 토큰 예산, 배치 순서/위치, 동시 적용 그룹을 편집한다.
- **탐색**: 자료 추가에서 캐릭터/로어/장면을 선택한다. 자료 검색은 캐릭터 이름/역할/태그, 로어 제목/태그/키워드, 장면 제목/언어에 적용한다. 태그와 활성화 키워드는 구분한다.
- **미리보기**: 선택한 시작 장면 또는 작품의 기본 시작 장면의 도입 대사, 연결 인물 이름, 언어를 반영한다. 비공개 배경/성격은 독자 대화에 그대로 표시하지 않는다. 로컬 키워드 테스트는 메시지 이력과 검색 조건, 우선도/배치 순서에 따른 동시 적용 그룹 선택을 확인한다.
- **검토**: 작품/캐릭터/장면/로어 필수 내용 누락을 안내하고 해당 편집기로 이동한다. 초안 JSON 내보내기 요청을 제공한다.

## 저장과 이전 초안

텍스트·작품 목록·독립 원본·휴지통은 `chat-kit-studio-workspace-v3`에 450ms 지연 자동 저장한다. v3가 없으면 기존 v2/v1을 작품 전용 자료로 이전한다. 기존 키는 수정하지 않는다. 잘못된 v3는 백업 저장 성공 후에만 대체하며, 읽을 수 없는 v3가 있을 때 이전 초안을 임의로 덮어 가져오지 않는다. 새 작업실은 빈 상태로 시작한다. 여러 작품, 독립 캐릭터/로어 원본, 연결 복사본과 휴지통을 지원한다. 다른 탭의 저장은 편집 중이 아닐 때 동기화하고, 저장 충돌은 덮어쓰지 않고 내보내기를 안내한다.

복원 시 필드 타입, 선택값, 로어 수치 범위, 중복 ID, 기본 장면/첫 인물/장소 참조와 이미지 목록을 검증한다. 장소의 분류를 변경하면 그 장소를 가리키던 장면의 시작 장소를 미선택으로 전환해 잘못된 참조가 남지 않도록 한다.

이미지 파일은 `chat-kit-studio-assets` IndexedDB에 보관한다. JSON은 이미지 목록만 포함하므로 원본 파일도 별도로 보관해야 한다. 브라우저 데이터 삭제나 다른 브라우저로 이동하면 이미지 재등록이 필요하다. UI에서 이미지 누락을 안내한다.

## 구성

- `apps/web/app/studio/page.tsx`: 진입 경로/메타데이터.
- `apps/web/components/studio/creator-studio.tsx`: 공통 틀/탐색/보관함/검토/편집 범위 분리.
- `project-editors.tsx`, `character-editor.tsx`, `lore-editor.tsx`: 편집 화면.
- `studio-controls.tsx`, `studio-dialog.tsx`, `studio-preview.tsx`: 공통 입력/대화상자/미리보기.
- `use-studio-draft.ts`: 저장/복원/이전 초안 유지.
- `apps/web/lib/studio-project.ts`, `studio-data.ts`: 스키마/샘플/참조 검증.
- `apps/web/lib/studio-workspace.ts`: v3 작업실 스키마/이전/원본 복사 연결/휴지통/참조 복구.
- `studio-assets.ts`: 브라우저 이미지 파일 저장.
- `studio-preview.ts`: 순수 로어 키워드 진단.

- JSON 다운로드 요청은 제공하지만 인앱 브라우저의 실제 파일 저장 완료는 검증하지 못했다.

## 남은 서버 연결 범위

서버 저장, 실제 공개/발행, AI 응답, CHARX 가져오기는 연결하지 않았다. 독립 원본과 작품 연결은 브라우저 내 복사본 방식으로 구현했다. AI에 적용할 비공개 설정/장면 옵션, 로어 토큰 예산과 삽입 위치는 초안에 저장하며 실제 모델 적용은 서버 연결 후 검증해야 한다.
