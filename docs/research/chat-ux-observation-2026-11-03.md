# 기존 채팅방 관찰과 채팅 UX·U19 설계 검토

조사일: 2026-11-03, Asia/Seoul. 대상: 사용자가 지정한 크랙 기존 채팅방 한 곳. 목적은 사용 흐름과 기능 규칙의 이해이며 화면 복제는 아니다. 상태: 관찰·사용자 교정·설계 제안 완료, 구현·Figma 작업 없음.

Windows Chrome에서는 창 목록·제목 조회까지만 성공하고 현재 URL 확인 단계에서 도구가 중단됐다. 이후 사용자가 같은 방을 Codex 내장 브라우저에 열어 주어 실제 화면·메뉴를 관찰했다. 이 기록은 해당 방·당일 UI에 한정한다. 뤼튼의 다른 서비스·다른 작품·계정·실제 모바일 기기는 조사하지 않았다.

## 1) 기능별 관찰·사용자 교정·추정·미확인 표

### 1.1 근거와 조작 범위

- **직접 확인:** 화면, 접근성 트리, 메뉴·도움말, 대표적인 기존 답변으로 확인한 사실. 설명 문구를 확인한 것과 실제 실행 결과를 확인한 것을 구분한다.
- **사용자 확인:** 이 조사 중 사용자가 설명하거나 교정한 사용 방식. 서비스 내부 구현을 검증했다는 의미는 아니다.
- **추정:** UI에서 유추한 흐름이나 아래의 우리 제품 설계 제안. 확인되지 않은 추정을 사실로 올리지 않았다.
- **미확인:** 생성·저장·상태 변경 제한, 관찰 환경, 설명 부족으로 확인하지 못한 내용. 미노출을 기능 부재로 해석하지 않는다.

처음 열린 화면과 최초 장면·최신 답변의 대표 구간을 보고 구조를 파악했다. 첫 접근성 조회에 로드된 이력이 넓게 포함됐으나, 추가 전체 이력 수집·내보내기·원문 파일 저장은 하지 않았다. 이후에는 메뉴·도움말과 필요한 항목 위주로 읽었다. 보고서에 대화 원문, 인물·프로필 이름, 노트의 사적 내용, 계정 잔액, 방 식별 URL을 옮기지 않았다. 스크린샷은 관찰 도구에서만 확인했고 별도 파일로 영구 저장하거나 외부 서비스·Figma에 업로드하지 않았다.

조작 기록과 제한:

- 메뉴·탭·도움말을 열고 닫았으며, 설정 값·프로필·노트·기억은 편집하거나 저장하지 않았다. 전송·리롤·이어쓰기·추천·이미지 생성·분기·삭제·복사·공유·구매·다운로드를 실행하지 않았다.
- **단축어 패널 버튼을 누르자 입력란에 `/`가 자동 표시됐다.** 목록과 탭을 관찰한 후 해당 한 글자를 지워, 최종 빈 입력란과 닫힌 패널을 화면으로 확인했다. 단축어 항목은 선택하지 않았다. 입력의 내부 임시저장 여부는 추적하지 않았으므로 저장 부수효과가 전혀 없었다고 단정하지 않는다. 추가 `/` 타이핑 실험은 하지 않았다.
- 스크롤된 상태에서 헤더 패널을 열려던 조작이 전체 검색 오버레이를 열었다. 검색·항목 선택·삭제 없이 즉시 닫고 같은 방으로 돌아왔다. 검색 내용은 조사 근거로 사용하지 않았다.
- 이미지 보관함 첫 조회에는 빈 상태 문구가 잠깐 나왔지만, 로딩 후 화면과 재조회에서 이미지 한 장으로 정정됐다. 최종 상태만 기능 판단에 사용한다.

같은 날 추가로 전달받은 사용 경험이다. 이번 보완에서는 브라우저를 다시 조작하지 않았다. 횟수·가격·페이지 크기는 회상의 대략값이며 서비스 전체의 고정 계약으로 확정하지 않는다. 앞 표의 미확인 항목을 사용자 경험 수준에서 보완하며 직접 실행 검증을 대체하지 않는다.

우선순위 보완: 방 이름·무한 스크롤·서술/대사 안내는 6절의 작성·읽기 기본 UX에 포함해 검토한다. 일러스트집은 U19의 표시 결과 조회·보존 접점에 포함한다. 이어쓰기·추천 답변은 별도 생성 기능 과제로 두고, 공통 요청·비용·이력 계약을 먼저 정한다. SNS/커뮤니티 형식은 초기에는 작가 문구·안전한 본문 렌더링 범위로 검토한다.

## 2) 현재 프로젝트에서 재사용할 부분과 새로 필요한 계약

### 2.1 현재 작업 트리와 후속 기록 대조

코드가 있다는 뜻과 운영·실기기 동작이 검증됐다는 뜻을 구분한다. 이번에는 서비스를 실행하거나 DB·외부 AI를 호출하지 않았다.

| 영역 | 현재 코드·후속 기록에서 확인 | 재사용 | 새로 필요한 계약 |
| --- | --- | --- | --- |
| 작성란·요청 복구 | 계정/방별 초안 localStorage, pending 요청 sessionStorage, 중복 실행 가드. 결과가 불확실하면 같은 키로 확인. 종료 실패가 retryable이면 새 answerKey를 마련하는 경로 | 초안·포커스·IME 보호, 불확실 요청 복구 | 문구 출처/버전·삽입 동작, 한 답변용 추가 지시, 저장 상태·기기 동기화 |
| 본문·조회 | 본문은 `p`의 문자열 출력. 고정 첫 장면은 별도 표시. 커서 동기화·history_revision 변경 시 전체 교체 | 안정적인 ID·revision·계정/방 격리·이력 세션 | 안전한 본문 렌더러, 이미지/서술/상태 블록, 대규모 이력 표시·읽는 위치 보존 |
| 답변 생성 | 입력이 현재 마지막 사용자 메시지 ID/revision이어야 함. 성공 답변이 뒤에 붙으면 이 검증 조건을 충족하지 않음 | 생성 ID·멱등키·실행권·확정된 프롬프트·가격/usage·원자적 완료 | 성공 답변 리롤의 기준 문맥·후보 그룹·선택·추가지침·충돌. 기존 API에 새 키만 보내는 것으로 해결 불가 |
| 실패·불확실 복구 | U17/U18 후속에 영속 복구 상한·대기·격리·감사와 저장 결과 재사용이 정리됨. 브라우저 대기 중단은 서버 취소가 아님 | 이미 수행한 외부 호출을 다시 부르지 않는 복구 원칙 | 비용 발생 가능 새 생성과 상태 재조회 UX 구분. 대기 중 리롤·분기 정책 |
| 변경·되돌리기 | PUT은 마지막 사용자 메시지 교체. DELETE는 지정 메시지를 포함한 이후 이력 되돌리기. 내부 캐릭터 교체는 공개 AI 편집 API와 다름 | 인가·revision·pending 충돌·같은 방 잠금·기억 무효화 | 대안 채택·분기는 별도 유스케이스. 기존 DELETE를 후보 선택이나 방 복사로 재해석하지 않음 |
| 자동 기억 | 자체 HTTP는 없고 공개 service/types로 조회·요약·임베딩·검색·작업을 제공. 근거 ID/위치/revision/digest, history_revision, 작업 소유권·기한, 변경 시 무효화 | 자동 요약 엔진·근거 검증·늦은 결과 거절·읽기 값 타입 | 소유자 HTTP 조회, 사용한 기억/갱신 상태 표시, 사용자 고정·교정 계층, 분기와 후보 선택에 맞는 근거 범위 |
| 노트·개인 메모·페르소나 | 조사한 채팅 HTTP/UI에 전용 관리 계약 없음. prompt는 runtime.settings를 참조 자료로 운반할 기반이 있으나 계정 프로필 목록·방별 적용 서비스는 확인되지 않음 | 공개 값 타입과 프롬프트 조합 경계 | 개인 메모의 비전달, 지속 노트의 적용 버전, 프로필 원본/방별 적용, OOC 일회 범위. 캐릭터의 persona_prompt를 사용자 페르소나로 재사용하지 않음 |
| 작가 자료·수동 로어 | **10-16 분석의 manual 미지원 설명은 현재 코드와 다름.** 현재 허가된 발행 스냅샷 ID의 수동 활성화, 답변 요청 manual_entry_ids, 프런트의 이번 답변 적용 체크박스가 연결됨. semantic 자동 선택은 여전히 미지원 | 출처·스냅샷·요청 범위를 확인하는 선택 경계 | 로어 활성화와 문구 삽입/OOC의 의미를 분리. 개인 템플릿을 작가 로어로 저장하지 않음 |
| 이미지 원본·발행 | 기존 CharacterImage는 캐릭터+감정 태그 UNIQUE와 캐릭터당 기본 이미지 부분 UNIQUE. 정확한 감정 조회와 기본 조회가 별도. 미디어 ready·참조·발행 스냅샷·정리 수명 기반 존재 | 기존 제약·미디어 소유권·스냅샷·URL/업로드 호환 | 감정 외 상황/장면 조건·우선순위·동률·대체값·판단 시점, 불변 이미지 결과·접근 권한 |
| 스튜디오 이미지 | 이미 `portrait / expression / scene` 분류와 mediaId 업로드를 사용. 현재 발행 조립은 `studio:{asset id}:{usage}` purpose의 **character asset**으로 연결함 | 이미지 등록·분류·업로드 영수증·발행/스냅샷 흐름 | 기존 감정 이미지와 스튜디오 asset의 관계를 정합화. 프런트 분류가 있다는 이유로 채팅의 자동 상황 선택이 완성됐다고 보지 않음 |
| 표시 이미지 상태 | messages에는 emotion_tag가 있지만 공개 MessageResponseDto에 이미지 선택 결과 필드가 없고 현재 본문 UI도 문자열. 답변/분기별 미디어 선택 보존 계약은 조사 범위에서 확인 안 됨 | 메시지·생성·상품 스냅샷 식별자 | 선택된 미디어/발행 이미지 ID·정책 버전·수동/자동·대체 사유·본문 위치를 후보/메시지와 연결 |
| 방·버전·비용 | 최초 snapshot의 첫 대사/시작 옵션과 현재 버전의 참여자/runtime을 구분. billing 예약·완료·해제와 생성 사실 보존. UI는 최근 답변 예약 가격 표시 | 최초 장면 보존·발행 버전 경계·생성 영수증 | 분기 출처와 승계 범위, 설정 revision, 후보별 가격/정산 조회. 방 복사로 과거 생성·청구 사실을 새 청구로 복제하지 않음 |

### 2.2 제안하는 공통 의미 계약

아래는 **설계 제안**이다. 테이블명·엔드포인트·구현 방식은 확정하지 않는다.

| 개념 | 필요한 의미·최소 정보 |
| --- | --- |
| 문구 | 제목/호출어·출처(개인/작가/공유)·본문·버전·소유/가용 범위. 삽입 후 전송 전 검토. 공유 원본 변경과 개인 복제본 변경 구분 |
| 앱 실행 명령 | 실행할 기능·대상·인가·예상 비용·확인 단계. 문구 본문에 `/리롤`이 적혔다고 자동 실행하지 않음 |
| 설정 적용본 | 계정 기본값·방별 선택·이번 요청 override를 구분하고 생성 시작 때 유효 버전을 고정. 작가 발행 설정과 이용자 override의 허용 범위 명시 |
| 노트/메모/페르소나 | 사용자 지속 노트, 비전달 개인 메모, 자동 기억, 사용자 프로필을 별도 소유 개념으로 관리. 각각 AI 전달 여부·수정 버전·분기 승계 명시 |
| OOC·리롤 지침 | 한 답변 또는 특정 후보 생성에만 붙는 지시와 지속 노트를 구분. 원문 대사/사실 기억으로 자동 승격하지 않음. 적용 사실·범위를 표시 |
| 답변 후보 | 기준 사용자 입력·후보 그룹·생성 ID·추가 지침·문맥 적용본·선택 후보·후속 이력 기준. 생성된 후보와 사용자가 채택한 후보를 구분 |
| 분기 | 출처 방·기준 메시지/revision·선택 후보·기준까지의 이력·시작/발행 버전·노트/프로필/기억의 승계 정책·이미지 결과. 사용자 범위의 분기 멱등키 |
| 자동 기억 근거 | 원문 위치·revision/digest·분기/활성 후보 기준·생성/검색 준비 상태·선택에 사용된 버전. 분기 지점 이후의 사실이 이전 분기에 섞이지 않게 검증 |
| 이미지 결과 | 발행 이미지/미디어 참조·표시 순서/위치·선택 정책 버전·자동/수동·대체 여부. 현재 화면에서 크게 보는 이미지와 답변에 보존된 결과는 별개 |
| 요청·비용 | 새 생성·같은 결과 확인·후보 채택·방 생성의 동작 구분. 예상/예약/확정/해제·불확실 상태·무료 횟수 등 소비 여부를 명시 |

모듈 책임은 현 경계를 유지한다. conversation은 방·적용 설정·발행/시작 기준, chat은 메시지·후보·활성 이력·생성 사실, memory는 자동 기억/근거·무효화, prompt는 공개 값의 조합을 담당하는 방향을 제안한다. 작가 이미지 원본·발행 미디어는 character/product, 비용은 billing의 공개 계약을 재사용한다. 개인 문구·프로필의 소유 책임은 별도 확정하되 성격이 다른 데이터를 conversation.settings JSON 하나에 무차별로 넣지 않는다. 여러 책임의 실행은 기존 workflow/최상위 use case에서 공개 service/types로 조합하고 타 모듈 ORM/repository 직접 참조를 늘리지 않는다.

## 3) 채팅 화면 구성안

아래는 관찰을 참고해 우리 프로젝트에 제안하는 화면이며 경쟁 서비스 배치의 복제안이 아니다. 도식의 명칭·버튼은 확정 UI 문구가 아니다.

```text
작품/방 제목 · 적용 프로필 · 사용 중 발행본             기억과 설정
┌ 대화 이력 ───────────────────────────────┬ 필요할 때 여는 패널 ┐
│ 고정 첫 장면                            │ 유저 노트 / 자동 기억 │
│ 사용자 입력                            │ 프로필 / 개인 메모    │
│ 답변: 서술·대사·이미지·상태 블록         │ 적용 범위·저장 상태   │
│   후보 1/2 · 비교 · 다시 생성 · 더보기    │                     │
├ 이미지 상세·장면 정보는 요청할 때 펼침    ┴─────────────────────┤
│ [문구 /] [작성 도구]   이번 답변 지시: 한 번만                  │
│ 작성 중 본문                                                  │
│ 적용 정보·비용/처리 상태                         [메시지 보내기] │
└───────────────────────────────────────────────────────────────┘
```

### 3.1 입력창과 `/` 메뉴

- 기존 초안·IME·커서·실행 취소를 보존하고, 전송과 도구 열기를 분리한다. 단축어 패널을 여는 것만으로 초안에 문자를 넣어야 하는지는 재검토한다. 닫기는 편집 전 상태로 복구한다.
- 메뉴의 1차 구분은 **문구 넣기 / 앱 기능**으로 제안한다. 문구 안에서 개인·작가·공유 출처를 표시한다. 작가 문구의 빈 상태·로딩·오류를 구분하고 공유 목록이 일부일 때 전체 검색처럼 안내하지 않는다.
- 문구는 미리보기 후 삽입하고 전송은 이용자가 결정한다. OOC 템플릿은 내용 형식이며 앱 실행 권한을 갖지 않는다. 출처·적용 범위를 한 줄로 보여준다.
- 별도 ‘이번 답변 지시’ 입력은 기본 한 답변 범위로 제안한다. 지속시키려면 유저 노트에 저장하는 명시 동작을 둔다. 현재 코드에 이 계약이 이미 있다는 뜻은 아니다.
- 생성 기능에는 실행 직전에 비용/무료 횟수 소비 여부를 표시한다. 확인 불가 상태는 소비 없음으로 표시하지 않는다.

### 3.2 노트·기억·페르소나 패널

| 탭 | 전달/적용 의미 | 표시 내용 |
| --- | --- | --- |
| 유저 노트 | 방의 지속 참고 자료 | 저장본/편집 중 구분, 글자/예산, 다음 요청부터 적용할 버전, 비용 영향 |
| 자동 기억 | 원문에서 생성·검색되는 기억 | 요약과 원문 근거, 마지막 갱신 범위, 준비/실패 상태, 이번 답변 참고 여부. 초기에는 읽기부터 |
| 프로필 | 계정 소유 자료 중 방별 선택 | 현재 적용 프로필·버전, 원본 수정과 방 적용 변경의 차이, 분기 승계 안내 |
| 개인 메모 | 기본 AI 비전달 | ‘나만 보는 메모’ 표기와 저장 상태. 노트에 옮길 때 별도 확인 |

자동 기억의 추가·교정은 기존 요약 원본을 덮어쓰기보다 사용자 고정 사실/교정 자료로 관리하는 방향을 제안한다. 기억에 적힌 지시를 서비스 규칙으로 승격하지 않는다. 원문 수정·후보 변경 뒤 오래된 기억을 그대로 보여주거나 사용하지 않도록 갱신 상태를 드러낸다.

### 3.3 답변별 리롤·분기 메뉴

- **같은 요청으로 결과 확인:** pending/불확실 요청의 상태 확인. 새 후보 생성과 다른 버튼·설명을 사용한다.
- **저장된 입력으로 답변 재시도:** 종료 실패 후 새 시도가 가능한 경우. 기존 입력과 비용 조건을 보여준다.
- **다시 생성:** 성공한 답변에서 추가 지침·적용 설정·예상 비용을 검토하고 새 후보를 만든다. 생성 중 기존 답변을 유지한다.
- **후보 선택/비교:** 받은 후보를 열람·채택하는 동작. 추가 생성 호출과 비용이 발생하지 않도록 설계하는 안이다. 채택한 답변만 활성 문맥으로 쓰고, 과거 생성·청구 사실은 유지한다.
- **여기서 새 방으로 분기:** 기준 메시지/후보와 이어받는 노트·기억·프로필·이미지·작품 버전을 요약한다. 원래 방으로 돌아갈 출처 링크를 둔다. 저장 범위·비용은 확정 정책에 맞춰 표시한다.
- **이후 이력 되돌리기:** 파괴적 영향 범위를 따로 보여준다. 후보 선택·분기의 구현 편의 때문에 기존 이력을 자동 삭제하지 않는다.

후속 대화가 이미 있는 과거 답변의 후보를 바꾸려면, 조용히 후속 이력을 바꾸기보다 새 분기로 계속하는 정책을 우선 제안한다. 고정 첫 대사는 현재 가짜 메시지 ID가 없으므로 메시지 리롤/되돌리기 대상으로 취급하지 않는다. 최초 장면에서 분기를 지원할지는 별도 계약으로 정한다.

### 3.4 이미지·장면 표시

- 한 답변 안의 여러 이미지와 위치를 표현할 수 있는 본문 블록을 제안한다. 큰 현재 이미지 하나만 방 상태에 저장하면 과거 답변·후보를 재현할 수 없다.
- 기본은 발행된 작가 이미지의 선택·표시로 두고, **새 이미지 생성은 별도 유료/무료 소비 기능**으로 분리한다. 경쟁 서비스에 생성 진입점이 있다는 이유로 U19에 이미지 생성 공급자를 필수 추가하지 않는다.
- 이미지 상세에서는 필요한 범위에서 장면/분류·선택 방식·대체 여부를 보여준다. 내부 프롬프트나 비공개 작가 조건 전체를 노출하지 않는다.
- 이미지 보기/접기·배경 확대 등 읽기 환경설정은 보존된 이미지 선택을 바꾸지 않는다. 이미지를 숨겼다가 다시 보거나 방에 재접속해도 같은 후보의 같은 결과를 읽는다.
- MEMO 같은 텍스트 블록은 우선 안전하게 렌더링한다. 앱이 관리하는 상태 패널을 도입한다면 상태 필드·계산·근거·후보/분기 보존을 따로 설계한다. 텍스트에서 수치를 읽었다고 신뢰된 게임 상태로 저장하지 않는다.

### 3.5 기기별 접근 제안

넓은 데스크톱은 선택형 옆 패널, 좁은 화면은 같은 내용을 하단 시트/전체 패널로 여는 안을 제안한다. 입력란의 문구 버튼, 각 답변의 더보기, 기억/프로필 진입은 모든 폭에서 남긴다. hover만으로 기능을 발견하게 만들지 않고 아이콘에 접근 이름을 붙인다. 모바일의 길게 누르기·스와이프를 필수 경로로 정하지 않는다. 실제 모바일 키보드·safe area·터치·모달 스크롤은 후속 검증 대상이다.

## 4) 공통 설계에서 먼저 결정할 질문

권장 시작안은 의사결정용 제안이며 확정 요구사항이 아니다. ‘사용자 확인’은 크랙의 사용 경험 설명이고 우리 제품 정책 승인은 별개다.

| 결정 질문 | 권장 시작안 | 결정/검증할 경계 |
| --- | --- | --- |
| 설정은 계정·작품·방·요청 중 어디에 적용되는가? | 계정 기본값 위에 방별 선택, 한 답변 지시는 요청 override. 작가 발행 제약과 이용자 선택을 분리 | 적용 가능한 항목, 우선순위, 버전 고정, 다른 방 동시 수정 |
| 변경은 언제 유효해지는가? | 생성 준비 시 settings/profile/note 버전을 고정하고 이후 변경은 다음 새 요청부터 | pending 중 변경·다른 탭 충돌·동일 키 재조회. 기존 실행 설정을 바꾸는 재시도 거절 |
| 리롤은 어떤 문맥을 재사용하는가? | 기준 입력·당시 적용본을 표시하고 추가 지침을 후보에만 기록 | 현재 노트/프로필로 새로 생성하는 옵션 여부, 모델·이미지 정책 변경, 후보별 비용 |
| 후보 채택 뒤 후속 이력은 어떻게 되는가? | 후속 이력 없는 끝 답변은 선택 변경, 과거 답변은 새 분기로 계속하는 정책 우선 | 기존 후속 답변의 종속성, 기억 무효화·revision, 동시 채택 충돌 |
| 새 분기는 무엇을 이어받는가? | 기준까지 활성 이력과 노트·프로필 적용본·적합한 자동 기억, 선택된 이미지 결과를 명시적으로 승계 | 사용자 경험의 ‘그대로’와 내부 복사 구현을 분리. 기준 이후 사실·다른 후보·pending 작업·원장 승계 금지/허용 정책 |
| 자동 기억의 근거와 무효화 단위는? | 원문 ID/revision/digest·분기·활성 후보 기준으로 유효성 검증. 사용자 교정은 별도 계층 | 기존은 파괴적 변경 때 방 전체 기억 무효화. 새 분기에서 근거 재매핑·재사용/재생성·미완료 표시 |
| OOC는 한 번만 어디까지 영향을 주는가? | 한 생성의 지시 자료로 저장하고 지속 노트와 분리. 지시문을 자동으로 사건 기억에 포함하지 않음 | 생성된 이야기의 결과는 이후 이력에 남음. ‘한 답변 적용’이 모든 후속 영향 소멸을 뜻하지 않음 |
| 이미지 선택 결과는 언제 무엇에 고정되는가? | 해당 답변 후보 완료와 함께 불변 참조·정책 버전·순서 저장 | 후보 재선택·분기·작품 새 발행·원본 삭제·수동 변경·접근 권한. 장면 상태와 읽기 설정 구분 |
| 선택 실패·대체 이미지는 무엇인가? | 명시 우선순위·동률 처리·기본/없음·대체 사유를 정책으로 정의 | 감정·장소·사건 조건의 충돌, 같은 이미지의 여러 분류 연결, ‘기존 유지’가 새 답변에 미치는 영향 |
| 요청 멱등성과 비용 표시는? | 입력 저장/새 생성/후보 채택/분기에 각자의 안정 키·revision. 기존 결과 조회는 새 생성으로 취급하지 않음 | 예약과 확정·해제, 불확실 외부 호출, 무료 횟수, 선택/분기의 비용 정책. 잔액 차이로 비용 추정하지 않음 |
| 분기와 기존 발행본·미디어 보존은? | 출처의 검증된 스냅샷과 미디어 참조를 보존하고 새 방에서 독립 변경 | 최초/현재 발행본 차이·가용성·허용된 업데이트·미디어 보존 수명·삭제/복원 |

우선 합의할 최소 묶음은 **설정 적용본, 활성 답변 이력, 분기 기준, 이미지 결과의 소유 위치**다. UI부터 붙인 뒤 이 네 개를 정하면 기억·과금·발행 경계까지 다시 바꿀 가능성이 크다.

## 5) U19의 범위와 별도 채팅 기능 과제의 경계

| 범위 | U19에서 다룰 내용 | 별도 과제와의 접점 |
| --- | --- | --- |
| 이미지 표현·분류 | 감정 외 장면·상황·맥락, 후보와 조건의 다대다 가능성, 기본값/유일성 범위 | 구조화 게임 상태·새 이미지 생성 공급자는 별도 |
| 선택·전환 | 우선순위·동률·기본/없음·대체·자동/수동·선택 시점. 단일 emotion_tag 조회만으로 충족했다고 보지 않음 | 리롤 추가 지침이나 OOC가 선택에 미치는 영향은 공통 요청 계약과 합의 |
| 스튜디오·발행 | 기존 portrait/expression/scene·asset·미디어 업로드를 재사용해 등록/분류/조건/미리보기와 실제 표시의 정책을 일치 | 문구 허브·프로필 관리·일반 채팅 설정은 별도 |
| 채팅 표시·보존 | 표시 DTO/블록·고정 선택 결과·후보/메시지/분기에서 이미지 결과를 참조할 인터페이스 | 후보 그룹·활성 선택·분기 엔진 전체는 별도 채팅 과제. 접점과 보존 요건은 U19 설계에서 먼저 확정 |
| 발행본·저장소 | 편집 원본·발행 스냅샷·기존 방 참조와 미디어 수명을 보존 | U28의 업로드 잠금/deadline 잔여와 U08/U23의 공급자·reader 수명 경계 유지 |
| 호환·제약·오류 | 기존 URL/업로드·감정/기본 이미지·스튜디오 asset 데이터의 이전/복구, 동시 편집·첨부·발행·제약 오류 | 현재 UNIQUE 근거를 지우거나 먼저 제약을 제거하지 않음. 충돌 번역만으로 완료 불가 |

별도 채팅 기능 과제는 문구 관리·공유, OOC 적용 범위, 사용자 노트/개인 메모/프로필, 기억 열람·교정, 성공 답변 후보 생성·선택, 분기·이력 모델이다. 이들을 U19의 이름 아래 한 번에 구현할 필요는 없다. 다만 U19 이미지 결과를 저장할 단위와 이력 변경 신호를 먼저 합의해야 두 작업이 충돌하지 않는다.

U19 완료 판단은 기존 재정의 문서를 유지한다. 구조·선택 정책, 스튜디오/채팅/발행 흐름, 기존 자료 호환·전환과 회귀 검증을 모두 다뤄야 한다. 이번 조사 문서나 경쟁 서비스의 이미지 관찰만으로 완료 처리하지 않는다.

## 6) 설계·구현 우선순위

| 순서 | 설계/작업 | 이유·완료 기준 |
| --- | --- | --- |
| 0 | 공통 의미 결정과 계약 예시 | 노트/메모/기억/프로필, 재시도/리롤, 되돌리기/선택/분기, 발행/방별 설정, 현재 표시/보존 결과를 분리. 4절 질문과 정상·실패·동시 변경 예시 승인 |
| 1 | U19 표현·선택·발행·보존 설계 | 기존 이미지/asset/미디어 구조의 연결·호환 계획을 먼저 정함. 상황/감정 충돌·동률·기본/없음·옛 발행본·여러 본문 이미지·결과 재현 예시로 검증 |
| 2 | 작성·읽기 기본 UX와 문구 삽입 | 기존 초안/요청 복구 위에 작성 도구·출처별 문구·안전한 렌더러. 패널 열고 닫기 때 초안/커서 보존, 선택만으로 전송/소비 없음. 좁은/넓은 화면·IME 확인 |
| 3 | 노트·프로필 적용과 기억 읽기 | 설정 버전·다음 요청 적용, AI 비전달 메모, 인가된 기억 조회/원문 근거·처리 상태. 사용자 교정 쓰기는 읽기 계약 안정 후 |
| 4 | U19 이미지 흐름 구현·호환 검증 | 작가 등록→발행→대화 선택→표시→재접속 보존을 같은 정책으로 연결. 기존 데이터·미디어 참조·권한·동시 변경·대체 결과 회귀 |
| 5 | 성공 답변 리롤 후보·채택 | 기준 문맥·추가 지침·후보 보존·활성 선택·비용/멱등성. 실패 복구와 구분, 중복 클릭/응답 유실에도 생성·청구 중복 없음 |
| 6 | 분기와 기억·이미지 승계 | 기준 시점 이력·노트·프로필·기억·이미지의 일관된 새 방 생성. 원본 보존, 기준 이후 기억 누출 없음, 중복 분기 요청·실패 복구 |
| 7 | 고급 기능 | 공유 문구 관리, 기억 교정/고정, 구조화 상태 패널, 별도 이미지 생성은 수요·비용·권한 계약을 확인한 뒤 분리 구현 |

우선순위 0~1은 병행할 수 있는 설계 논점이며 구현을 시작했다는 뜻은 아니다. 후보/분기 전체 구현 전에도 U19를 진행할 수 있지만, 보존 결과 인터페이스를 함께 설계해야 한다.

**이번 산출물 검증:** 문서만 추가했다. 제품 코드·DB·설정·기준선·기존 분석 문서는 변경하지 않았다. Markdown 구성·내부 자료 링크·작업 트리 변경 범위를 확인했다. 제품 동작/패턴 변경이 없어 backend quality·업무 테스트·빌드·외부 AI 실행은 하지 않았다. 실제 모바일, 리롤 실행·후보 선택, 분기 생성, 이미지 선택·생성·과금은 후속 검증으로 남는다.
