# 크랙 실제 채팅 UX 시험과 U19 설계 검토

2026-11-03~04에 Codex 내장 브라우저로 개인 채팅방 한 곳과 그 분기를 시험했다. 생성 8회에 무료대화권 7회와 크래커 102개를 사용했다.

## 1. 시험 조건과 소비 기록

- 대상: 사용자가 내장 브라우저에 연 「탑 등반물의 히든 NPC가 되었다」. NPC 시작 설정으로 새 개인 채팅방 생성. 다른 이용자의 파티에는 참여하지 않음.
- 한도: 실제 크래커 차감 합계 1,500개. 목표 약 20회는 의무가 아님. 시작 잔액 3,230개, 작품 무료권 7회(6일 남음)를 화면에서 확인.
- 모드: 하이퍼챗 1.0. UI는 Opus 4.6 활용·권장·102개로 설명한다. 이는 서비스 표시이며 공급자 호출을 검증한 것은 아니다.
- 생성 전 새 방 출력 한도를 제작자 권장 3,000토큰(무료권 적용 중 최대 180개)에서 기본 1,000토큰(최대 0개)으로 변경·저장. 생각 조절은 1.5배 이상에서만 가능하다는 안내. 노트 비어 있음·확장 OFF. 기존 프로필 선택 유지, 원본 편집 없음.
- 무료권 안내: 답변마다 1회, 재생성·이어서 생성 포함. 페이블챗 제외. 기본 제공량 초과·노트 확장은 별도 크래커. 전체 가격 규칙으로 일반화하지 않는다.
- 기준 이야기: 성인 마을 수리공이 등반자의 배낭·등불을 수선한다. 비민감 가상 사실만 입력.
- 모델은 고정, 출력 비교 때만 한 항목 변경. 예상 최대 비용을 확인할 수 없는 소비 동작은 보류한다.

분기 생성, 후보 왕복 선택, 노트 편집, 이름 변경은 생성 횟수에서 제외했다. 분기·이름 변경 뒤 잔액은 3,128개였다. 작업별 영수증은 확보하지 못했다. 요금 안내·대화권 잔여·잔액을 대조한 결과 미확정 소비는 없으며, 예산 잔여는 1,398개다.

## 3. 근거 수준별 관찰

- 직접 확인: 작가 단축어 `/커뮤`를 선택하면 편집기에 호출어가 삽입되고 패널이 닫힌다. 선택만으로 전송되지 않았다. 본문 전체가 펼쳐지는 형태는 아니었다.
- 직접 확인: E01의 별표 서술은 사용자 말풍선에서 별표 없이 표시. 생성 답변에 작가 이미지 두 곳과 서술·인물 대사가 표시됨. 말미는 닫히지 않은 별표가 문자로 남으며 문장 중간 종료.
- 직접 확인: E01 완료 직후 추천 문구 3개가 이미 나타남. 추천 버튼을 누르지 않은 상태이므로 명시적인 추천 생성 시험과 구분한다.
- 직접 확인: E02 이어쓰기 완료 뒤 추천 3개 내용이 바뀌었고 작성 중 인사 초안은 유지됐다. 생성 도중 추천·모드 선택은 비활성화됐지만 작성란의 초안은 남아 있었다.
- 직접 확인: 일반 대사도 사용자 말풍선으로 저장됐으며, 서술 입력과 별개로 응답을 생성했다. 원문이 별표로 감싸진 서술은 별표 제거 표시, 일반 대사는 그대로 표시됐다. 별도 역할 DB 필드/모델 파싱 방식은 미확인.
- 직접 확인: 리롤 후 `답변 비교 2/2`에서 기존 후보 선택 시 1/2로 바뀌고 원래의 미완성 INFO와 이미지가 복원. 다시 2/2 선택 가능. E03은 이미지 2개, E04는 3개이며 사건 원인·이야기 시각도 달라졌다. 두 후보의 이미지 참조 순서는 비교 메뉴에 본문 표기로 나타났지만 보고서에 전체 URL·원문을 복사하지 않는다. 내부 저장 스키마는 미확인.
- 직접 확인: 추천 옆 연필(접근 이름 `답변 수정`)을 누르면 기존 초안 소실 경고·취소/확인. 확인하자 추천문구로 초안이 교체되고 전송하지 않았다. 이 버튼은 기존 AI 답변 편집과 의미가 달라 접근 이름 개선 필요.
- 직접 확인: 추천 **본문** 클릭은 연필과 달리 즉시 전송·생성했다. 당시 편집기는 비어 있었다. 초안이 있는 상태의 본문 클릭은 별도 미확인. 추천 후보 생성 비용과 선택 후 본 답변 생성 비용을 구별해야 한다.
- 직접 확인: E05의 일회 OOC는 짧은 형식·상태창 생략이 반영됐지만 정확히 세 문장 조건은 맞지 않았다. 모델이 지시를 일부 따른 사례이지 앱이 일회 OOC를 별도 필드로 해석·강제한다는 증거는 아니다.
- 직접 확인: E06은 다시 여러 문단·이미지 4개·INFO 형식으로 출력. 의자에 앉아 기다리는 이야기 상태는 이어졌다. 일회 형식 지시가 끝난 것과 그 답변에서 벌어진 사건이 사라지는 것은 다르다.
- 직접 확인: 개인 `/일기`, 공유 요약 문구를 각각 선택해 입력란의 호출어 삽입·전송 대기를 확인한 뒤 시험 초안만 비웠다. 개인/공유 문구는 실제 전송하지 않았다. 호출어 표시가 연결된 문구 객체인지 일반 문자열인지, 원문이 서버에서 어떻게 추가되는지는 미확인. 동일 이름 충돌은 기존 항목을 변경하지 않고 안전하게 구성할 근거가 부족해 미실행.
- 직접 확인: `/커뮤` 결과는 대화 본문 안의 제목·표·게시글·댓글 목록 형식이었다. 작성자/추천/조회수는 이야기 속 가상 표시로서 실제 커뮤니티 활동·다른 이용자 글 조회로 확인된 것이 아니다. 별도 SNS 애플리케이션이 실행됐다는 증거는 없다. 중간에 끊긴 댓글과 이어쓰기 버튼도 보였다.
- 사용자 확인: 이전 조사에서 OOC 기본 한 답변, 자동 기억 생성, 방별 프로필, 분기의 노트·기억·프로필 승계를 설명받음. 이번 실험에서 검증한 항목만 직접 확인으로 추가한다.
- 추정: 자동 추천의 생성 모델·과금 묶음, 단축어의 내부 프롬프트 위치, 실제 토큰 종료 사유는 화면만으로 확정하지 않는다.

## 4. 기존 보고서의 확인·정정

[기존 관찰 보고서](chat-ux-observation-2026-11-03.md)의 S3 빈 작가 목록은 이전 작품에 한정된다. 이번 작품에는 커뮤·요약·디버그·사칭·이미지의 5개 작가 문구가 보였다. S1의 선택 결과는 호출어 삽입·전송 대기까지 직접 확인했다.

기존 R1·R2의 후보 보존과 선택, B1의 기준 메시지 포함 및 이후 이력 제외, N1의 노트 승계·분기 후 독립 변경을 직접 확인했다. 분기 전후 장기·단기 기억이 모두 0개였으며 더 많은 메시지가 필요하다는 안내가 있었다. 비어 있지 않은 자동 기억의 승계는 이전 사용자 설명 수준으로 남는다.

## 5. 재시도·리롤·선택·이어쓰기·분기 계약

| 동작 | 우리 프로젝트의 요청·비용·이력 계약 제안 |
| --- | --- |
| 실패·응답 유실 | 불확실한 요청은 기존 키로 상태를 읽는다. 재시도 가능한 종료 실패만 같은 입력 revision으로 새 시도를 만든다. 크랙에서 실패를 유발하지 않았다. |
| 성공 답변 리롤 | 기준 입력과 문맥 버전을 고정하고 지침을 새 후보에 붙인다. 새 생성의 비용·이미지·본문을 독립 보존한다. |
| 후보 선택 | 후보 ID와 활성 이력 revision만 변경한다. 이미 생성한 비용과 이미지를 재사용한다. 후속 메시지가 있는 과거 후보 전환은 별도 정책이 필요하다. |
| 이어쓰기 | 끊긴 후보와 그 끝을 기준으로 새 생성 구간·비용을 연결한다. 원래 이미지 위치와 새 구간 이미지 위치를 모두 재현한다. |
| 분기 | 기준 답변을 포함하는 새 방과 출처를 만든다. 이력 경계, 노트·프로필을 가져오는 시점, 유효한 기억의 근거 범위를 각각 기록한다. 과거 생성 원장은 출처를 참조한다. |

## 6. 프로젝트·U19 영향과 우선순위

기존 보고서의 현재 코드 대조를 재사용하고 핵심 코드를 다시 확인했다. `get_answer_input`은 마지막 사용자 메시지 ID/revision을 요구하므로 성공 답변 리롤은 새 요청 키만으로 해결되지 않는다. 공개 MessageResponseDto에는 이미지 결과가 없고 본문 UI는 문자열 p 출력이다. 스튜디오의 portrait/expression/scene asset과 기존 감정 이미지 제약을 보존하면서 표시 결과 계약을 확장해야 한다.

1. **공통 계약을 먼저 결정한다.** 활성 후보·이어쓰기 구간·분기 기준·설정 적용 버전을 함께 정의한다. 노트처럼 분기 시점의 값을 받을 자료와 메시지 시점까지 제한할 기억 근거를 구분한다.
2. **U19는 답변 재현을 완료 기준으로 삼는다.** 후보마다 발행 이미지 참조와 본문 위치를 순서대로 보존한다. 같은 이미지가 한 후보 안에서 반복될 수 있다. 후보 전환·분기·재접속 때 같은 순서를 복원하는 사례를 검증한다. 작가 원본 목록, 실제 표시 이력, 사용자 앨범은 별개 조회로 설계한다. [U19 재정의](../audits/2026-10-26-pattern-standardization/U19-REDESIGN-NOTE.md)
3. **입력·비용 UX를 분리한다.** 문구 삽입, 추천 편집, 즉시 전송을 버튼 이름과 초안 경고로 구별한다. 실행 전에 기본 비용·무료권·길이 초과 최대치를 함께 제시한다. 사용량은 요청별 영수증으로 대조할 수 있게 한다.
4. **채팅 후속 과제로 구현한다.** 리롤·이어쓰기·분기 엔진, 노트·기억 근거 조회, 추천과 문구 관리는 U19의 이미지 보존 인터페이스에 연결한다. 실패 복구·작품 스냅샷·기억 revision 검증은 현재 모듈 책임을 재사용한다. [기존 코드와 아키텍처 대조](chat-ux-observation-2026-11-03.md)
