# 프런트·백엔드 통합 실행 계획

사용자 승인 범위: 확인된 통합 문제의 로컬 수정, 필요한 회귀 테스트와 빌드, 결과 기록은 추가 확인 없이 진행한다. 기존 작업과 API DTO를 보존한다.

## 1단계 — 기존 채팅 경로 안정화 (로컬 수정·검증 완료)

- 메시지 커서를 끝까지 조회하여 100개 이후 메시지와 새 답변을 표시한다.
- 최근 대화와 작성 중 메시지를 사용자별로 분리한다. 소유자를 알 수 없는 기존 실제 대화 캐시는 새 계정에 귀속시키지 않는다.
- Access 만료 시 Refresh를 연결하고 동시 요청·탭 사이 회전을 직렬화한다. 갱신 응답 유실 시 무조건 재전송하지 않는다.
- CSRF 실패는 토큰을 재발급하여 한 번 복구한다. 복구되지 않은 인증 오류에서도 저장된 메시지의 답변 재시도 정보를 유지한다.
- 완료 조건: 관련 회귀 테스트, 프런트 타입 검사·프로덕션 빌드, 실행 가능한 백엔드 테스트 통과. DB/외부 서비스 없이 건너뛴 검증은 구분해서 기록한다.

## 2단계 — 계정·목록 서비스 흐름

- 가입 → 이메일 인증 → 로그인, 비밀번호 재설정, 로그아웃 화면과 API를 연결한다.
- 공개 작품 목록과 소유 대화 목록 API의 정렬·커서·이미지·미리보기 계약을 정의한다.
- 브라우저 목록을 서버 조회로 전환하고 사용자 전환·다른 기기·삭제된 작품을 검증한다.
- 완료 조건: 신규 사용자 진입부터 대화 재접속까지 브라우저 E2E 통과.

## 3단계 — 스튜디오 서버 저장·발행

- 스튜디오 작품/캐릭터/로어/시작 장면 필드와 기존 백엔드 DTO의 매핑 표를 먼저 작성한다.
- 로컬 ID와 서버 ID 매핑, 저장 충돌, 이미지 업로드, 중간 실패 복구를 구현한다.
- 비공개 저장 → 검증 → 발행 → 실제 작품 상세 → 채팅을 순서대로 연결한다.
- 완료 조건: 저장 후 새 브라우저에서 복원, 재저장 중복 방지, 발행본으로 첫 답변 생성.

## 4단계 — 운영 준비

- 테스트용 PostgreSQL과 mock LLM으로 전체 경로를 자동화한다.
- 크레딧 잔액·가격·부족 오류 화면, 요청 중단·재시도·동시 요청을 검증한다.
- 실제 공급자·실결제·배포 검증은 사용할 환경과 자격증명이 준비된 뒤 별도 수행한다.

## 2~4단계 후속 실행 (2026-10-07)

- 계정: 가입·이메일 인증·비밀번호 재설정·로그아웃 화면과 기존 인증 API를 연결했다. 메일 링크가 프런트로 돌아오도록 `AUTH_PUBLIC_ORIGIN` 설정을 문서화했다.
- 목록: 승인된 공개 발행본의 고정 제목·설명·커서 목록과 소유 대화의 마지막 메시지 목록 API를 추가하고 홈·둘러보기·내 대화에 연결했다. 서버 목록은 사용자 전환 시 비우고 다시 조회한다. 작품/대화 이미지는 기본 표지를 사용한다.
- 스튜디오: 필드 매핑을 [별도 문서](studio-server-mapping-2026-10-07.md)에 기록했다. 소유자별 JSON 초안 저장·revision 충돌·응답 유실 재시도·다른 기기 가져오기를 연결했다. 이미지 없는 작품의 **첫 발행**은 캐릭터·로어·시작 장면·모델·릴리스 노트를 한 트랜잭션으로 생성하고 같은 문서의 재시도는 결과를 재사용한다. 이미지 원본이 서버에 저장되지 않는 점을 저장·가져오기 화면에서 알린다. 후속 버전 구현 전에는 발행본의 변경 저장을 거절해 미발행 공개 설정 변경을 막는다. 후속 버전과 이미지 업로드는 남아 있다.
- 채팅 운영: 크레딧 잔액, 생성 요청에서 기록된 예약 가격, 부족/설정 오류를 보여주고 대기 중단 뒤 같은 요청 키로 결과를 다시 확인할 수 있게 했다. 요청 전 확정가격 미리보기는 현재 서버 API에 없다.
- 검증: 프런트 26개 테스트·타입 검사·Next 프로덕션 빌드 통과. 백엔드 전체 425개 통과·255개 환경 조건으로 건너뜀. 새 스튜디오→첫 답변 HTTP E2E 테스트는 작성했으나 PostgreSQL 부재로 건너뛰었다.

남은 검증은 실제 PostgreSQL에서 Alembic/초기 SQL 일치, 메일 링크, 새 브라우저 복원·발행·첫 답변, 동시 저장 충돌 및 크레딧 차감이다. Docker 데몬과 `TEST_DATABASE_URL`·`TEST_AUTH_DATABASE_URL`·`DATABASE_URL` 및 공급자 키가 현재 환경에 없어 수행하지 못했다. 실제 공급자·실결제·배포 검증도 별도 환경에서 필요하다.
