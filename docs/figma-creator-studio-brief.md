# 캐릭터 채팅 제작 스튜디오 — Figma 제작 명세

## 사용자 요구

- 기존 프런트 디자인은 참고하지 않고 새로 설계한다.
- 기본 테마는 화이트, 다크 테마는 짙은 중성 그레이다.
- 초보 제작자도 쉽게 시작하면서 세부 설정을 확장할 수 있어야 한다.
- 관리 단위는 작품, 캐릭터, 로어북 세 가지다.
- 폴더 탐색, 태그와 태그 검색, 로어 우선도와 세부 조건을 지원한다.
- 결과물은 편집 가능한 Figma 레이어와 재사용 컴포넌트로 구성한다.

## 디자인 방향

작업에 집중할 수 있는 편집 도구. 넓은 여백, 명확한 타이포그래피, 절제한 경계선, 낮은 그림자 강도. 장식적인 그라디언트와 큰 홍보 배너는 사용하지 않는다. 주요 행동은 대비가 높은 버튼, 일반 행동은 중립 버튼으로 구분한다.

한글 중심 UI. 글꼴은 Figma에서 사용 가능한 Pretendard 또는 Noto Sans KR를 확인해 결정한다. 제목 24/32, 섹션 제목 18/26, 본문 14/22, 보조 정보 12/18을 초기 기준으로 사용한다.

## 정보 구조

전역 보관함: 작품 / 캐릭터 / 로어북. 각 보관함에서 폴더, 검색, 태그 필터를 사용할 수 있다. 작품 편집에서는 해당 작품에 연결된 자료만 탐색기에 표시한다. 원본 보관함과 작품 내부 구성을 구분한다.

태그는 정리용 메타데이터다. 로어 활성화 키워드는 별도의 입력이며 태그 변경으로 동작이 바뀌지 않는다.

## 핵심 화면

### 01. 내 작업실

- 전역 사이드바: 작품, 캐릭터, 로어북, 최근 작업.
- 상단: 현재 보관함 제목, 검색, 새로 만들기.
- 폴더 탐색과 태그 필터; 카드/목록 전환.
- 항목 정보: 이름, 간단한 설명, 태그, 상태, 최근 수정.
- 빈 상태: 첫 작품 만들기와 기존 자료 가져오기.
- 예시 콘텐츠는 독립적인 가상 판타지 세계로 작성한다. CHARX 원본 이미지나 본문은 업로드하지 않는다.

### 02. 새 작품 시작

- 제목과 짧은 소개를 입력한다.
- 기존 캐릭터 연결 또는 새 캐릭터 만들기.
- 시작 장면을 작성하고 편집기로 진입한다.
- 진행률과 뒤로 이동을 제공하며 입력을 유지한다.
- 로어 고급 설정을 완료해야만 진입할 수 있게 만들지 않는다.

### 03. 작품 편집기 — 기본

- 1440px 데스크톱 기준.
- 상단: 작품 이름, 초안 상태, 저장 상태, 테스트, 발행.
- 왼쪽 약 260px: 작품 개요, 등장인물, 로어북 폴더, 시작 장면, 플레이 옵션.
- 중앙: 선택한 항목의 편집기. 기본 설정만 표시.
- 오른쪽 약 360px: 필요할 때 여는 미리보기/테스트 패널.
- 캐릭터·로어 연결, 복제, 폴더 이동, 태그 변경을 메뉴에서 제공.
- 사이드바에서 항목 종류·현재 선택·미저장 오류를 구분한다.

### 04. 캐릭터 편집

- 이름, 공개 소개, 비공개 성격/말투, 대사 예시.
- 접을 수 있는 관계와 이미지 관리 섹션.
- 이미지에는 표정/용도, 기본 이미지 표시, 검색과 일괄 등록 동작.
- 공유 원본을 편집하는지 작품 전용 설정을 편집하는지 상단에 표시.
- 원본 수정 / 작품 전용 설정 / 별도 복사를 구분한다.

### 05. 로어 편집 — 기본과 고급

- 기본: 제목, 종류, 본문, 정리 태그, 활성 여부.
- 적용 조건: 항상 / 특정 단어 / 시작 장면 / 등장인물 / 상태 조건.
- 조건을 선택하면 필요한 입력만 표시.
- 키워드는 칩 입력; 여러 키워드 중 하나/모두 등 지원 범위를 명확하게 표현.
- 고급 접기: 포함 우선도, 검색 범위, 배치 순서/위치, 토큰 예산, 동시 적용 제한.
- 포함 우선도 기본 표현: 필수 / 높음 / 보통 / 낮음.
- 필수 항목이 문맥 한도를 넘으면 해결이 필요한 상태를 표시.
- 태그와 활성화 키워드는 별도 라벨과 짧은 도움말을 사용.

### 06. 테스트 채팅과 진단

- 테스트 시작 전 장면·플레이 옵션 선택.
- 대화와 진단을 탭 또는 패널로 전환.
- 적용된 로어: 제목, 이유, 포함 우선도.
- 제외된 로어: 조건 불일치 / 예산 부족 / 비활성 / 동시 적용 제한.
- 누락된 이미지 연결과 문맥 사용량 표시.
- 실제 실행 시 비용 정보를 제공할 자리 확보.

### 07. 발행 검토

- 작품 소개, 연결된 캐릭터/로어, 시작 장면, 버전 설명을 검토.
- 차단 오류와 권고 사항을 구분하고 해당 편집 위치로 이동.
- 원본 수정, 초안 저장, 발행 버전의 관계를 명확히 표시.

## 컴포넌트와 Figma 구성

- Foundations: Light/Dark 색 변수, 간격, 모서리, 글자 스타일.
- Components: 버튼, 입력, 선택, 태그 칩, 폴더 행, 탐색 항목, 항목 카드, 접기 영역, 상태 배지, 진단 행, 대화 말풍선.
- 컴포넌트 상태: 기본, 호버, 선택, 포커스, 비활성, 오류.
- Screens Light / Screens Dark: 핵심 편집 화면을 동일 구조로 비교.
- Prototype: 보관함 → 새 작품 → 편집 → 로어 고급 → 테스트 → 발행 검토를 연결.
- Notes: 서버 미지원 기능과 화면 동작만 구현한 프로토타입을 표시.

## 평가 시나리오

1. 초보자가 캐릭터 3명, 로어 10개로 작품을 만들고 테스트할 수 있다.
2. 숙련자가 캐릭터 30명, 로어 100개에서 폴더/검색/태그로 필요한 항목을 찾는다.
3. 특정 로어가 적용되지 않은 이유를 테스트 화면에서 확인한다.
4. 공유 캐릭터의 작품 전용 수정이 다른 작품에 영향을 주지 않는다는 것을 이해한다.
5. Light/Dark 양쪽에서 글자, 선택, 오류가 분명하다.
6. 1024px에서는 테스트 패널을 접거나 별도 보기로 전환해 편집 영역을 확보한다.
