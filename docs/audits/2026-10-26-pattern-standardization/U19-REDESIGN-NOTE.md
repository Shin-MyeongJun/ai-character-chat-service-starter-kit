# U19 범위 재정의 — 이미지 기능 전반의 구조 개편

작성일: 2026-10-30 (Asia/Seoul)

상태: **a1 설계 확정. a2~a9 구현 및 검증 예정.**

이 문서는 2026-10-30의 범위 재정의 기록이다. 이후 확정된 정책, 데이터·조회 계약,
구현별 인수 조건은 [U19 a1 설계 계약](U19-A1-IMAGE-CONTRACT.md)에 있다.

## 사용자 요구

U19를 이미지 기본값·감정 태그 중복의 오류 처리 개선 수준으로 다루지 않는다.
감정 외에도 상황·장면·대화 맥락에 맞는 이미지를 지원할 수 있도록 이미지 기능 전반을
개편해야 한다. DB 오류 번역이나 기본 이미지 중복 처리만 수정해 U19를 완료하지 않는다.

기존 감사에서 확인한 UNIQUE 제약과 오류 노출 경로는 유효한 설계 근거로 보존한다.
제약이 없다는 주장으로 바꾸거나, 개편을 위해 기존 제약을 먼저 제거하지 않는다.

## 함께 검토할 범위

- **이미지 표현과 분류:** 감정 중심 구조를 넘어 상황·장면·맥락을 어떻게 표현할지,
  이미지와 분류/조건의 연결 및 중복 허용 단위를 정한다. 구체적인 스키마는 아직 정하지 않는다.
- **선택·전환 정책:** 현재 맥락에 맞는 이미지의 선택 기준, 우선순위, 기본값과 대체 이미지,
  전환 시점, 자동/수동 선택 여부를 일관된 정책으로 정한다.
- **스튜디오와 채팅:** 작성자의 이미지 등록·분류·연결·미리보기와 실제 채팅 표시가 같은
  정책을 따르도록 관리 흐름·API·표시 모델을 함께 검토한다.
- **발행·보존·저장소 경계:** 원본 편집과 발행 스냅샷의 분리, 기존 대화의 이미지 참조,
  업로드된 미디어의 연결/정리 수명을 고려한다. 기존 발행본과 미디어 참조가 의도치 않게
  바뀌지 않도록 변경 범위를 명시한다.
- **호환과 전환:** 기존 기본 이미지·감정 태그·URL/업로드 미디어를 새 구조로 다루는 방법,
  API 및 저장 데이터 호환, 필요한 경우의 데이터 이전·복구 전략을 정한다.
- **제약·오류·동시성:** 새 정책에 맞는 유일성·기본값 범위와 충돌 처리, 동시 편집/첨부/
  발행 계약을 검증한다. 오류 개선은 전체 개편에 포함되는 하위 항목이다.

위 항목은 설계 검토 범위이며 특정 테이블·선택 알고리즘·자동화 기능을 확정한 요구사항은
아니다. 전반 개편의 정책과 경계를 구체화한 뒤 구현 단위를 나누며, 이번 문서로 코드를
변경하거나 migration을 실행하지 않는다.

## 완료 판단과 관련 과제

U19는 감정 외 상황별 이미지 요구를 반영한 구조·선택 정책과 작성/채팅/발행 흐름,
기존 자료의 호환·전환 및 회귀 검증을 다뤄야 한다. 기존 제약 오류 처리만 개선한 상태는
U19 완료로 표시하지 않는다.

U28의 업로드 중 잠금·해싱·스트림 수명은 이미지 기능과 접점이 있으므로 책임 경계를
함께 확인한다. U08/U23의 공급자·reader 수명과 기존 발행본 보존 계약도 고려한다.

U19 이외의 다음 작업은 U25의 남은 태그 이름 resolve 배치화를 우선 추천한다.
그다음 U29의 SDK 예외 분류·메모리 작업 기한을 별도로 검토할 수 있다. U16의 태그 정책
공통화는 U25와 같은 영역을 건드리므로 순서를 조정한다. 해당 작업은 이번에 시작하지 않았다.

## 이번 변경과 검증

원본 감사의 U19 제목·범위를 갱신하고 표준화 REPORT에 범위 조정과 다음 후보를 기록했다.
이 문서는 구현 완료 기록이 아니다. 제품 코드·테스트·DB·공통 검사 설정은 변경하지 않았고
테스트도 재실행하지 않았다. 기존 staged/unstaged/untracked 변경을 보존했으며
별도 대화·서브에이전트·commit/push는 만들지 않았다.
