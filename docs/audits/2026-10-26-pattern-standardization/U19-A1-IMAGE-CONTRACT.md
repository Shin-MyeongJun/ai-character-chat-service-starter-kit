기존 감사의 유일성 제약과 오류 경로를 설계 근거로 유지한다. UX 실험에서는 답변 후보 전환과 분기에서 당시 이미지와 순서가 복원됐고, 앨범의 해금 규칙은 확인되지 않았다. 아래 해금 기준은 사용자 결정에 따른다. [U19 범위](U19-REDESIGN-NOTE.md) · [채팅 UX 실험 §2·§5~7](../../research/chat-ux-experiment-2026-11-03.md)¹

¹ a1 작성 시 실험 문서는 원본 작업 트리에서 읽었다. 기준 커밋에는 이 파일이 없으며 해당 문서가 통합되면 상대 링크가 해석된다.

## 사용자 확정 정책

- 캐릭터에는 표정과 상황, 로어북 항목에는 상황을 등록한다. 첫 장면의 이미지는 작가가 위치를 명시한다.
- 작품 내 수집 항목 ID와 불변 파일 버전을 구분한다. 기존 항목의 파일 교체는 해금을 유지하며, 앨범에는 발행된 새 파일을 표시한다. 같은 태그로 새로 만든 항목은 별도로 해금한다. 과거 본문은 표시 당시의 파일을 유지한다.
- 채팅용 발행 이미지가 하나 이상이면 작품 앨범을 표시한다. 선택한 첫 장면 또는 확정된 답변에 등장한 항목을 계정×작품×수집 항목 단위로 자동 해금한다.
- 활성 로어로 상황 이미지 후보를 좁힌다. 삽입 여부와 위치는 확정 답변에 기록한다.

## a1 구현 기본값

### ID, 소유권, 수명

| 키 | 생성·해석 규칙 |
| --- | --- |
| `product_id` | 기존 서버 작품 UUID. 소유권·해금·현재 앨범 조회의 범위다. |
| `image_item_id` | 작성 클라이언트가 항목 추가 시 한 번 만드는 UUID. 서버가 작품에 귀속시키며 논리 키는 `(product_id, image_item_id)`다. 교체·태그 수정·재정렬은 ID를 유지한다. 삭제가 초안 CAS로 저장되면 ID를 폐기하며 신규 항목에 재사용할 수 없다. 현재 발행본은 후속 발행까지 그 항목을 보유한다. 다른 작품으로 복사하면 새 ID를 발급한다. |
| `file_version_id` | 작품 소유 업로드가 발급하는 UUID. 저장 공급자·객체·바이트와 MIME을 고정한다. 같은 업로드 요청의 재전송은 같은 ID를 돌려준다. 새 교체 업로드는 새 ID를 받는다. |
| `product_snapshot_id` | 기존 발행 UUID. 항목 ID와 파일 버전의 쌍, 대상·태그·정렬, 시작 장면 블록을 한 버전에 동결한다. |
| 대상과 시작 옵션 | 초안은 문서 로컬 `character.id` / `lorebooks[].id` / `scenes[].id`를 사용한다. 발행은 같은 스냅샷의 `product_character_id` 또는 `(lorebook_snapshot_id, lore_entry_id)`와 기존 `start_set_id`로 변환한다. `lore_entry_id`는 활성화 결과의 entry ID다. |
| 본문의 발생 위치 | 답변은 `(conversation_id, message_id, revision, block_index)`, 첫 장면은 `(conversation_id, initial_snapshot_id, start_set_id, block_index)`로 찾는다. `block_index`는 0부터 시작하며 같은 항목이 반복돼도 각각 보존한다. |

- 작품 모듈이 새 채팅 이미지와 파일 버전의 소유권·첨부·발행·앨범 해금을 담당한다. 캐릭터 또는 로어 대상은 작품 구성 안의 분류다. 저장소 모듈은 바이트와 reader 수명을 담당한다. 스튜디오 조립부는 공개 서비스로 작성/발행을 조합하고, conversation/chat은 첫 장면/답변의 발생 사실을 각자의 저장 트랜잭션에서 작품 공개 해금 서비스에 전달한다.
- 기존 캐릭터 미디어는 기존 캐릭터 API, 초상, 공개/발행 연결과 기존 스냅샷에서 계속 사용한다. 신규 채팅 항목은 전용 비공개 작품 파일 버전을 가리킨다. 기존 미디어를 재사용하려면 소유·ready를 확인해 명시적으로 작품 저장 공간에 복제하고 새 파일 버전으로 등록한다. 기존 `media_id`나 URL을 새 항목의 파일 참조로 받을 수 없다. 기존 공개 경로로 이미 볼 수 있는 이미지의 바이트는 그대로 공개된 상태이므로, 공개된 적 없는 이미지가 필요한 경우 작가는 별도 파일을 업로드한다.
- 업로드는 `(owner_id, product_id, request_id)`와 요청 지문으로 재시도한다. 다른 바이트나 메타데이터로 같은 키를 쓰면 충돌이다. 발행은 정확한 초안 revision에서 모든 대상·배치 참조와 동일 작품의 ready 파일을 검증한다. 스냅샷과 영수증을 원자적으로 확정한다. 파일 교체 또는 이미지 제거가 포함된 변경은 새 스냅샷을 만든다. 동시 발행/첨부/정리는 기존 초안 잠금 순서와 파일 상태 잠금으로 직렬화한다.
- 정리는 초안, 보존 중인 스냅샷, 내구 저장된 성공 준비 결과, 보존 중인 첫 장면/메시지 참조가 모두 해제된 파일만 대상으로 한다. 마지막 참조 해제 또는 미첨부 업로드의 ready 전환 후 최소 24시간을 초안 저장·재시도에 제공한다. 잠금 아래 참조를 다시 확인하고 삭제 중 파일에는 새 참조를 금지한다. 버전의 실행 만료는 파일 정리 신호로 쓰지 않는다. 해금 기록에는 파일 FK가 필요 없다. 삭제된 항목은 현재 앨범에서 빠지며 과거 본문과 최초 해금 기록은 각자의 보존 정책을 따른다.

### 초안과 발행 예시

아래는 관련 필드만 담은 예시다. 초안은 기존 camelCase 문서에 `chatImageItems`와 장면의 `openingImagePlacements`를 추가한다. `imageItemId`는 등록 시 고정하고, 업로드 전에는 `fileVersionId: null`을 허용한다. `tags`는 공백 정리 후 빈 값을 거부하며 같은 항목의 중복 태그는 정리한다. 항목 간 같은 태그는 허용한다.

```json
{
  "product_id": "10000000-0000-4000-8000-000000000001",
  "revision": 12,
  "document": {
    "chatImageItems": [
      {
        "imageItemId": "20000000-0000-4000-8000-000000000001",
        "fileVersionId": "30000000-0000-4000-8000-000000000002",
        "target": {"kind": "character", "id": "repairer"},
        "kind": "expression",
        "tags": ["미소"],
        "alt": "수리공이 미소 짓는다"
      },
      {
        "imageItemId": "20000000-0000-4000-8000-000000000002",
        "fileVersionId": "30000000-0000-4000-8000-000000000003",
        "target": {"kind": "lore_entry", "id": "workshop"},
        "kind": "situation",
        "tags": ["수리점"],
        "alt": "등불이 켜진 수리점"
      }
    ],
    "scenes": [
      {
        "id": "arrival",
        "opening": "수리점 문이 열렸다.",
        "openingImagePlacements": [
          {"imageItemId": "20000000-0000-4000-8000-000000000002", "afterParagraph": 1}
        ]
      }
    ]
  }
}
```

`afterParagraph`의 0은 본문 앞, 양수는 1부터 세는 문단 뒤다. 빈 줄로 문단을 나누되 원문 구분자는 텍스트 블록에 보존한다. 같은 위치는 배열 순서대로 배치하고 범위 밖 위치, 누락 대상, 로어 표정 및 업로드 미완료 참조는 발행 오류로 반환한다. 초안에서 항목 삭제 시 해당 장면 배치를 함께 제거하거나 작가에게 수정 대상으로 표시한다.

아래 내부 스냅샷에는 저장소 키나 전송 URL이 없다. 발행 배열의 순서는 앨범과 선택 후보의 기본 순서다. `starts[].content_blocks`에 들어가는 이미지 참조는 이 스냅샷 안에서만 해석한다. 공개 시작 옵션 목록에는 잠긴 원본을 미리 전송하지 않는다.

```json
{
  "product_id": "10000000-0000-4000-8000-000000000001",
  "product_snapshot_id": "40000000-0000-4000-8000-000000000012",
  "chat_image_items": [
    {
      "image_item_id": "20000000-0000-4000-8000-000000000001",
      "file_version_id": "30000000-0000-4000-8000-000000000002",
      "target": {"kind": "character", "product_character_id": "50000000-0000-4000-8000-000000000001"},
      "kind": "expression",
      "tags": ["미소"],
      "alt": "수리공이 미소 짓는다"
    },
    {
      "image_item_id": "20000000-0000-4000-8000-000000000002",
      "file_version_id": "30000000-0000-4000-8000-000000000003",
      "target": {
        "kind": "lore_entry",
        "lorebook_snapshot_id": "60000000-0000-4000-8000-000000000001",
        "lore_entry_id": "60000000-0000-4000-8000-000000000002"
      },
      "kind": "situation",
      "tags": ["수리점"],
      "alt": "등불이 켜진 수리점"
    }
  ],
  "starts": [
    {
      "start_set_id": "70000000-0000-4000-8000-000000000001",
      "content_blocks": [
        {"type": "text", "text": "수리점 문이 열렸다."},
        {
          "type": "image",
          "image_item_id": "20000000-0000-4000-8000-000000000002",
          "file_version_id": "30000000-0000-4000-8000-000000000003",

        }

```

기존 초안·스냅샷에서 새 필드가 빠져 있으면 빈 이미지 목록으로 읽는다. 기존 `portrait/expression/scene`과 외부 URL은 자동 승격하지 않는다. 명시적 가져오기는 기존 원본 및 구버전의 연결을 보존한다. 기존 캐릭터 이미지 제약과 API, 발행 영수증의 읽기 계약을 유지한다.

### 첫 장면, 답변과 해금

- 대화 생성 시 작품의 사용 가능한 최신 버전에서 시작 옵션을 확정한다. 옵션이 하나면 기존 자동 선택 규칙을 적용한다. 대화의 최초 버전과 선택 옵션을 저장하고 해당 옵션의 배치만 같은 트랜잭션에서 해금한다. 이후 버전 전환과 첫 장면 재조회는 최초 버전의 블록을 읽는다.
- 후보는 생성에 고정된 발행 스냅샷에서 만든다. 캐릭터 표정/상황은 해당 답변의 `product_character_id`에 한정한다. 로어 상황은 활성화된 `(lorebook_snapshot_id, lore_entry_id)`에 한정한다. 발행 순서로 최대 24개를 모델에 전달하고, 입력 예산이 부족하면 뒤에서부터 뺀다. 모델에 전달하는 정보는 이번 요청에서만 유효한 후보 키, 종류, 태그, 설명이다.
- 선택 기본값은 완성 본문에 대한 선택적 배치 제안이다. 내부 어댑터가 같은 생성 결과에서 텍스트와 별도의 `(candidate_key, after_paragraph)` 목록을 넘긴다. 서버가 후보 키와 문단 위치를 검사하고 본문 순서로 최대 3개를 적용한다. 같은 문단 내 순서는 제안 순서이며 같은 이미지 반복도 보존한다. 무제안·알 수 없는 키·잘못된 위치는 해당 삽입을 생략한다. 기본 이미지 자동 삽입과 사용자 문자열·외부 URL의 이미지 변환은 적용하지 않는다. a7은 적어도 한 채팅 실행 경로에서 배치 제안을 지원하며, 그 외 경로는 텍스트 답변을 그대로 지원한다.
- 성공한 답변을 확정하는 트랜잭션에서 메시지의 순서 있는 블록, 해금, 기존 생성 성공/과금 정산/기억 예약을 함께 커밋한다. 해금은 `UNIQUE(account_id, product_id, image_item_id)`에 대한 멱등 삽입이며 최초 성공 시각을 유지한다. 초안 미리보기, 선택하지 않은 시작 옵션, 후보 선정, 실패·취소·stale 결과는 해금 이벤트를 만들지 않는다. 되감기·삭제·후보 변경은 이미 얻은 해금을 취소하지 않는다.
- 이어쓰기·리롤·분기가 제공될 때 각 확정 답변/구간은 자기 블록을 고정한다. 이미 저장한 후보 선택과 이력 복사는 당시 순서와 파일 참조를 재사용한다. 이력 조작 엔진은 해당 채팅 과제에서 제공한다.

아래 메시지는 v11에서 확정됐고 v12에서 첫 번째 항목의 파일이 교체된 사례다. 기존 `content`는 텍스트 블록을 순서대로 이어 붙인 값이며 프롬프트·기억·구형 클라이언트가 계속 사용할 수 있다. `content_blocks`는 첫 장면/메시지 DTO에 선택 필드로 추가한다. 레거시는 누락 또는 null이면 `opening_message` / `content`를 렌더링한다. 새 형식에서 텍스트 전용 결과는 텍스트 블록 배열이다.

```json
{
  "id": "80000000-0000-4000-8000-000000000001",
  "conversation_id": "90000000-0000-4000-8000-000000000001",
  "revision": 1,
  "product_snapshot_id": "40000000-0000-4000-8000-000000000011",
  "content": "수리공이 웃었다.",
  "content_blocks": [
    {"type": "text", "text": "수리공이 웃었다."},
    {
      "type": "image",
      "image_item_id": "20000000-0000-4000-8000-000000000001",
      "file_version_id": "30000000-0000-4000-8000-000000000001",
      "alt": "수리공이 미소 짓는다",
      "content_url": "/conversations/90000000-0000-4000-8000-000000000001/messages/80000000-0000-4000-8000-000000000001/revisions/1/blocks/1/content"
    }
  ]
}
```

`content_url`은 읽기 DTO가 계산한다. 저장되는 이미지 블록에는 항목·파일 버전·대체 텍스트가 있고 배열 위치가 발생 위치다. 첫 장면 파일은 `/conversations/{conversation_id}/start/blocks/{block_index}/content`로 같은 방식으로 읽는다.

### 앨범과 파일 요청

- `GET /products/{product_id}/album`은 작품 접근권을 확인하고 `latest_snapshot_id`가 가리키는 발행본을 기준으로 조회한다. 버전 고정 방에서 열어도 이 기준은 같다. 최신 발행본이 없거나 만료됐으면 `product_snapshot_id: null`, `available: false`, 빈 배열을 돌려준다. 사용 가능한 최신 발행본에 항목이 없으면 해당 스냅샷 ID와 함께 `available: false`, 빈 배열을 돌려준다. 앨범을 열거나 새 버전을 보아도 해금은 발생하지 않는다.
- 앨범은 현재 항목 ID에 해금을 결합한다. 잠김 행은 항목 ID와 상태만 노출하며 이미지·썸네일·대체 텍스트를 노출하지 않는다. 파일 교체는 후속 발행이 완료되면 반영된다. 삭제된 항목을 오래된 방에서 뒤늦게 획득하면 해금은 기록되며 현재 앨범에는 나타나지 않는다.
- 새 파일 경로는 요청마다 인증과 권한을 확인한다. 앨범 파일은 작품 접근권, 최신 사용 가능 스냅샷의 정확한 항목·파일 버전, 요청 계정의 해금을 모두 검사한다. 잠김, 다른 계정/작품, 과거 URL의 버전 불일치와 미존재는 같은 404다. 클라이언트는 교체 후 과거 URL이 실패하면 앨범을 다시 읽는다. 작성자 미리보기는 작품 소유자 전용 경로를 사용하며 앨범의 해금에 영향을 주지 않는다.
- 과거 본문 파일은 요청 계정의 방 소유권과 조회 가능한 정확한 첫 장면/메시지 revision의 블록 소속을 검사한다. 작품 버전 만료는 새 대화·생성의 기존 제한에 적용하고, 보존된 본문 및 해당 바이트는 방에서 계속 열람한다. 앨범 해금이나 현재 스냅샷을 이 조회의 조건으로 삼지 않는다. 기존 작품/버전/캐릭터 미디어 경로의 만료 정책은 유지한다. 기존 제재·삭제로 방/본문 열람이 금지되거나 파일이 강제 제거된 경우에는 그 정책을 따르며, 조회 가능한 본문에서 파일만 유실됐으면 해당 위치의 대체 텍스트를 표시한다.
- 파일 응답은 기존 인증 스트림, `private, no-store`, MIME 검사와 reader 종료 계약을 재사용한다. 작품 채팅 파일을 기존 캐릭터 연결이나 기존 작품 스냅샷 미디어 경로로 읽을 수 없도록 소유 범위와 저장 경로를 분리한다. 공개 저장소 키·공개 CDN URL을 반환하지 않는다.

```json
{
  "product_id": "10000000-0000-4000-8000-000000000001",
  "product_snapshot_id": "40000000-0000-4000-8000-000000000012",
  "available": true,
  "items": [
    {
      "image_item_id": "20000000-0000-4000-8000-000000000001",
      "status": "unlocked",
      "file_version_id": "30000000-0000-4000-8000-000000000002",
      "alt": "수리공이 미소 짓는다",
      "unlocked_at": "2026-11-11T04:00:00Z",
      "content_url": "/products/10000000-0000-4000-8000-000000000001/album/items/20000000-0000-4000-8000-000000000001/files/30000000-0000-4000-8000-000000000002/content"
    },
    {
      "image_item_id": "20000000-0000-4000-8000-000000000002",
      "status": "locked"
    }

```

이 앨범 계정은 예시 첫 장면을 선택한 적이 없고, v11의 답변에서 첫 항목을 획득했다. 같은 `미소` 태그로 셋째 항목을 발행하면 별도의 잠김 행이 추가된다.

### 응답 유실과 복구

1. 생성 입력의 스냅샷·참여자·활성 로어에서 후보를 확정한다. 공급자 결과를 받으면 텍스트와 검증한 최종 블록을 함께 `result_ready`로 내구 저장한다. 이미지 없는 결과도 블록을 명시한다. 구형 staged payload는 텍스트 결과로 완결한다.
2. 같은 계정·`request_key`와 기존 요청 지문은 원래 `generation_id`로 재진입한다. 처리 중이면 기존 202 또는 `storage_pending_recovery` 경로를 사용한다. `result_ready` 복구는 저장된 블록으로 완료하며 최신 후보나 활성 로어를 다시 계산하지 않는다. 결과가 내구 저장되기 전에 중단되면 기존 실패/불확실성 정책을 적용한다.
3. 성공 응답에는 선택 필드 `message_id`를 추가해 같은 요청의 성공 재호출에도 동일한 메시지를 가리키게 한다. 클라이언트는 기존 대화 이력 동기화에서 저장된 메시지의 블록을 읽고 앨범 조회를 갱신한다. 같은 키는 공급자 재호출·재과금·중복 해금을 일으키지 않는다. 이력이 이미 제거된 경우 성공 상태는 유지하고, 조회 가능한 이력에서 제거된 본문을 되살리지 않는다. 새 키는 기존 정책상 재시도 가능한 종료 실패 또는 별도 생성 요청에 사용한다.
