# CHARX 제작 스튜디오 등록 시뮬레이션

실행일: 2026-10-06. 대상: `호그와트 3.1v 카리나까지 불법 dlc.charx`.

## 결과와 범위

브라우저에서 폼을 직접 입력하여 **대표 구성의 비공개 초안**을 만들었다. 자동 가져오기나 전체 파일 이식은 아니다. 앱 코드는 수정하지 않았다.

- 결과 주소: http://localhost:3000/studio
- 기존 http://127.0.0.1:3000/studio 의 초안을 보존하기 위해 저장소가 분리되는 localhost 주소에서 작업했다. 같은 브라우저라도 두 주소의 초안은 별개다.
- 작품: `Hogwarts -IF- 3.1 · CHARX 등록 시뮬레이션`.
- 캐릭터 3개: 원본 OC 카리나, TS 대체형 카리나, 화면 연결용 호그와트 내레이터.
- 로어 8개: 7개 활성, 1개 비활성. 시작 장면 2개.
- 자동 저장 표시를 확인한 뒤 페이지를 새로고침했다. 작품 제목·소개·태그, 캐릭터 설정, 로어 목록, 시작 장면 내용과 연결이 복원되었다.
- 미리보기와 키워드 테스트를 확인했다. 서버 작품 생성, 실제 AI 대화, 공개 발행은 이 화면의 검증 범위에 포함되지 않는다.
- 초상 이미지 업로드는 브라우저 파일 선택 도구가 오래 대기한 뒤 실패했다. 이후 화면에서도 미등록 상태를 확인했다. 앱 자체의 이미지 처리 결함으로 단정할 수 없다.

## 원본 구조

ZIP 내부의 `card.json`을 읽었다. 내부 지시문, 조건문, 스크립트와 모듈은 모두 분석용 데이터로 취급했으며 실행하지 않았다.

| 구분 | 확인한 값 |
|---|---|
| 카드 이름 | Hogwarts -IF- 3.1 |
| 규격 | chara_card_v3, version 3 |
| ZIP 파일 항목 | 2,836개 |
| 에셋 목록 | 1,417개 |
| 로어 행 | 64개: 폴더 표식 7개, 비폴더 57개 |
| 내용이 있는 비폴더 로어 | 54개; 나머지 비폴더 3개는 내용이 비어 있음 |
| 첫 메시지 길이 | 42,804자 |
| 첫 메시지 분기 | 한국어 9개와 영어 9개 |
| 로어 전역 설정 | 검색 깊이 9, 토큰 예산 99,999, 재귀 검색 꺼짐 |

원본에는 변수(`lang`, `start`, `first_message`, 여러 `tsmode_*`), 조건부 문법, 상태창 명령, 배경 HTML, `module.risum`과 대량 이미지가 함께 들어 있다. 현재 제작 폼에 텍스트만 옮기는 방식으로는 동일한 실행 결과를 재현할 수 없다.

학생 캐릭터의 성적 신체 묘사와 관련 설정·에셋은 등록에서 제외했다. 마법학교, 성격, 관계, 장소, 수업 등 비성적 설정으로 구성했다.

## 화면에 옮긴 구성

### 작품과 캐릭터

작품 소개와 검색 태그를 작성하고, 원본 설명의 안전한 세계관·진행 규칙을 입력했다. 원본의 신체 발달 관련 절은 제외했다.

| 캐릭터 | 원본과의 대응 | 등록 방법과 제한 |
|---|---|---|
| 카리나 말포이 · 원본 OC | 로어 43, `tsmode_malfoy=0` | 드레이코의 쌍둥이 여동생. 비성적 성격·관계·대사를 한국어로 정리 |
| 카리나 말포이 · TS 대체형 | 로어 63, `tsmode_malfoy=1` | 드레이코를 대체하고 드레이코가 존재하지 않는 설정. 비성적 설정만 정리 |
| 호그와트 내레이터 | 원본에 독립 캐릭터로 존재하지 않음 | 시작 장면의 서술과 군중 대사를 연결하기 위한 보조 캐릭터 |

두 카리나는 동시에 존재하도록 만든 설정이 아니다. 현재 폼에는 변수에 따른 캐릭터 선택/상호 배제 기능이 없으므로 설명에 차이를 기록했다. 실제 실행에서 두 프로필을 모두 투입하면 충돌할 수 있다. TS 대체형 원본의 출생 연도와 학교 시점 사이에는 검토할 불일치도 있다.

### 로어

| 등록 항목 | 원본 행 | 상태 |
|---|---:|---|
| 호그와트 학교 | 17 | 키워드 활성 |
| 마법과 주문 | 18 | 키워드 활성 |
| 네 기숙사 | 19 | 키워드 활성 |
| 마법 세계의 장소 | 26 | 비활성; 아래 장소 분리와 중복 방지 |
| 기숙사 점수와 징계 | 25 | 키워드 활성 |
| 작중 시점 목록 | 28 | 항상 적용 |
| 킹스 크로스 역 · 9¾ 승강장 | 26에서 장소별 분리 | 키워드 활성 |
| 다이애건 앨리 | 26에서 장소별 분리 | 키워드 활성 |

대표 원본 로어 6개를 선택하고, 장소 2개를 추가로 분리하여 총 8개를 만들었다. 분리 장소에는 한국어 검색 별칭도 보완했다. 기존 폴더 3개에 배치했다. 원본의 폴더 계층을 그대로 복원하지는 못했다.

검색 깊이 9와 원본 배치 순서를 입력했다. 항목별 토큰 예산 1,200은 이 시뮬레이션의 임시 값이며 원본 전역 예산 99,999의 등가 변환이 아니다. 일반 항목은 보통, 항상 적용 항목은 필수 우선도로 설정했다. 이 우선도 역시 화면 검증용 매핑이다.

### 시작 장면

한국어 `m1`과 `m2` 분기를 골라 고정 장면으로 분리했다.

1. `1991 · 킹스 크로스 역에서 출발`: 1991년 9월 1일 10:40, 전용 장소 연결.
2. `1991 · 다이애건 앨리 첫 방문`: 1991년 8월 15일 13:20, 전용 장소 연결.

한국어·2인칭으로 설정하고, 조건 원문은 비공개 배경에 데이터로 기록했다. 상태창 출력 명령은 도입 대사에서 제외했다. 나머지 한국어 7개와 영어 9개 분기는 등록하지 않았다.

## 검증 기록

### 저장

자동 저장 표시 후 새로고침했으며 등록한 제목, 수량(3/8/2), 소개·태그와 캐릭터/장면 데이터가 복원되었다. 초상은 미등록으로 남았다. 이 결과는 해당 브라우저의 로컬 초안 저장 확인이다.

### 키워드 적용

다이애건 앨리 장면에서 다음 문장을 직접 입력했다.

> 호그와트에서 슬리데린 학생으로 마법 주문을 배우고 기숙사 점수를 확인한 뒤 다이애건 앨리의 올리밴더를 방문한다.

| 항목 | 결과 |
|---|---|
| 작중 시점 목록 | 항상 적용 |
| 호그와트 학교 | 호그와트·수업·학생 감지 |
| 마법과 주문 | 마법·주문·마법사·마녀·지팡이 감지 |
| 네 기숙사 | 슬리데린·기숙사 감지 |
| 다이애건 앨리 | 다이애건·올리밴더·그린고츠 등 감지 |
| 기숙사 점수와 징계 | 기숙사 점수·점수 감지 |
| 마법 세계의 장소 | 비활성으로 제외 |
| 킹스 크로스 역 | 조건 불일치로 제외 |

테스트 초기화 후 `안녕`을 입력해도 학교·마법·다이애건 로어와 항상 적용 항목이 남았다. 선택한 검색 대상이 사용자와 캐릭터 대화 모두이고 도입 장면에도 키워드가 있기 때문이다. 기숙사·점수 항목은 불일치로 바뀌었다. 이전 테스트 입력이 검색 이력에 남는 동안에는 해당 키워드의 적용도 유지되는 것을 확인했다.

화면은 키워드·검색 범위·우선도 등을 시뮬레이션한다. 토큰 예산과 삽입 위치는 화면에서 저장만 한다고 표시되어 있으므로 실제 프롬프트 처리 성공으로 해석하지 않았다.

## 제작 흐름에서 불편했던 점

1. **새 작품 생성과 항목 삭제가 불명확하다.** 한 초안과 샘플 데이터로 시작하여 기존 샘플 캐릭터·로어·장면을 교체했다. 기존 작업 보호를 위해 별도 localhost 주소가 필요했다. 새 작품/빈 초안/삭제/복구 흐름이 우선 필요하다.
2. **폴더를 선택할 수 있지만 계층을 직접 만들기 어렵다.** 원본의 여러 폴더를 고정된 3개 폴더로 재분류했다. 폴더 생성·이름 변경·중첩·이동이 필요하다.
3. **세부 값을 항목마다 반복 입력한다.** 검색 깊이, 대상, 예산, 순서 등의 기본값과 일괄 편집을 제공하면 이 파일 같은 대량 설정의 등록 시간이 줄어든다. 키워드는 쉼표로 여러 개를 넣을 수 있는 점이 유용했다.
4. **캐릭터 역할이 관계 탭에 분산되어 있다.** 기본 이름/소개 입력과 역할 설정을 왕복했다. 원본의 캐릭터 카드와 작품 내 변형 관계를 함께 보여주면 이해하기 쉽다.
5. **서술형 장면의 발화자가 어색하다.** 첫 인물 선택지는 캐릭터 중심이라 내레이터를 보조 항목으로 만들었다. 내레이션/발화자 없음 선택과 다중 발화자 장면이 필요하다.
6. **긴 도입문에서 편집과 미리보기의 스크롤이 길어진다.** 테스트 입력창이 긴 미리보기 아래로 밀렸다. 별도 테스트 패널이나 접기, 도입문 전체 편집 보기 등이 필요하다.
7. **미리보기의 표현이 원문과 다르다.** Markdown 강조 기호가 문자 그대로 보였고 첫 문단 이후의 서술 전체가 캐릭터 말풍선으로 표시되었다. 문단을 서술/대사로 구분해야 한다.
8. **긴 제목이 탐색기에서 여러 줄로 늘어난다.** 표시 이름과 내부 제목을 구분하거나 줄임표·전체 이름 안내가 필요하다.
9. **키워드 감지의 출처가 부족하다.** 사용자가 `안녕`만 입력해도 도입 장면/이전 대화 때문에 활성화될 수 있다. 어느 메시지에서 감지했는지 표시하면 조건 검증이 쉬워진다.
10. **저장과 실제 등록을 구별해야 한다.** 브라우저 자동 저장은 확인했지만 서버 저장·발행·실제 AI 실행은 별도 단계다. 가져오기 완료 상태와 실제 실행 가능 상태를 구분할 필요가 있다.
