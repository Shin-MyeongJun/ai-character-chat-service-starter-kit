## Figma에서 편집 가능한 레이어 만들기

1. ZIP을 압축 해제합니다. Figma 데스크톱 앱에서 위 디자인 파일을 엽니다.
2. Plugins → Development → Import plugin from manifest에서 이 폴더의 `manifest.json`을 선택합니다. 메뉴 이름은 앱 언어에 따라 다를 수 있습니다.
3. 개발 플러그인 `모서리 · 발견 화면 시안 가져오기`를 실행합니다.
4. **편집 가능한 시안 생성**을 누릅니다.

플러그인은 새 페이지에 PC·모바일 × Light/Dark, 상태 보드 2개, 컴포넌트 보드 2개, 구현 메모를 생성하도록 작성했습니다. 원본 페이지를 수정하지 않으며 외부 네트워크를 사용하지 않습니다. Noto Sans KR Regular/Medium/Bold가 필요합니다.

색상은 의미 변수→원시 변수 별칭으로, 간격·모서리는 숫자 변수로 연결합니다. 플랜에서 여러 변수 모드를 허용하면 Light/Dark 모드를 사용하고, 허용하지 않으면 하나의 컬렉션 안에 Light/Dark 이름 공간을 분리해 동일한 시안을 생성합니다. 텍스트는 편집 가능하며 컴포넌트 속성으로 제목·설명·라벨 등을 바꿀 수 있습니다. 표지만 래스터 이미지입니다.

실행이 끝나면 생성 결과 JSON을 저장할 수 있습니다. 같은 완성 페이지가 있으면 중복 생성하지 않습니다. 오류가 나면 기존 `생성 중` 페이지의 변수와 컴포넌트를 재사용해 재개합니다. `Figma 검토 자료 저장` 버튼은 원본 PNG와 레이어 검증 기록을 ZIP으로 저장합니다.

## 조사한 화면과 기존 흐름

| 경로 | 현재 기능 | 디자인 진행 |
|---|---|---|
| `/` | 소개, 추천 샘플, API 공개 작품 | 이번 메인 시안 |
| `/explore` | 검색, 장르, 공개 작품, 다음 페이지 | 메인 방향 확정 후 |
| `/works/[id]` | 작품 소개, 시작 장면 선택, 대화 시작 | 메인 방향 확정 후 |

| `/chats/[id]` | 메시지, 캐릭터 응답, 재시도, 크레딧 | 메인 방향 확정 후 |
| `/login` | 로그인과 복귀 경로 | 메인 방향 확정 후 |
| `/register`, `/verify-email` | 가입과 이메일 확인 | 메인 방향 확정 후 |

## 참고 사이트와 디자인 방향

https://crack.wrtn.ai/ 의 2026-10-12 실제 브라우저 화면을 확인했습니다. 좌측 탐색, 상단 검색, 가로 장르 칩, 추천 배너와 이미지 카드 중심의 구조를 참고했습니다. 모서리의 코랄 포인트와 따뜻한 중성 배경, 기존 이야기 제목·소개를 유지했습니다. 기존 CSS의 시스템 글꼴 묶음 대신 편집·구현 시 일관성을 위해 Noto Sans KR를 디자인 글꼴로 제안했습니다.

공개 API에 아직 표지·장르·작가명·성인 권한 필드가 없으므로 해당 UI는 디자인 계약 제안입니다. 상세 메모는 미리보기의 `구현 메모`와 `design.js`의 `notes`에 있습니다. 운영 수치나 랭킹을 지어내지 않았습니다.

## 성인 필터

라벨은 **성인 콘텐츠 포함**입니다. 확인된 성인에게만 표시하고 기본 OFF입니다. OFF는 일반 콘텐츠만, ON은 성인 콘텐츠까지 포함한다는 뜻입니다.

미성년·로그아웃·연령 미확인·권한 로딩 중에는 필터와 공간을 모두 제거합니다. 서버가 허용한 결과만 표시하며 클라이언트 계산으로 권한을 올리지 않습니다. 필터 전환 오류 시 마지막 확인 상태로 복귀하고, 계정·권한 변경 시 이전 결과 캐시를 비우도록 구현 메모에 기록했습니다.

## 검증 범위

`node build.cjs`는 컴포넌트 변형의 중복, 화면 참조, 이미지·아이콘·텍스트 스타일 참조를 검사하고 플러그인 파일을 조립합니다. `node --check plugin.js`로 구문을 확인했습니다. 브라우저 시각·상태 검토는 `qa.json`, 실제 Figma 생성 결과는 `native-figma-report.json`, 최종 글꼴·크기·넘침·변수 검증은 `native-previews/native-qa.json`에 기록했습니다.
