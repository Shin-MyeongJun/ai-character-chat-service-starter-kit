## 11월 9일 크랙 실화면 확인

사용자가 열어 둔 채팅방을 내장 브라우저의 좁은 화면에서 확인했다. 모바일 기기에서 따로 시험한 결과는 아니다. 대화·노트·메모리 원문, 계정·재화 정보, 화면 이미지는 Figma 및 이 문서에 옮기지 않았다.

| 확인한 UI | 모서리에 반영한 설계 |
| --- | --- |
| 작성란 옆 `/`에서 단축어 패널 진입. 목록은 전체·제작자·내 단축어·허브로 나뉜다. 패널을 열자 입력에 `/`가 들어갔다. | 작성란 옆 `/` 버튼으로 목록 진입. 패널 열기 자체로 초안에 문자를 추가하지 않는다. 단축어를 고르면 `/일기`, `/묘사 강화` 같은 이름만 제거 가능한 칩으로 보인다. 목록에는 기능 설명을 붙이고 프롬프트 전문은 노출하지 않는다. |
| 최신 답변 아래 메시지 옵션을 열면 분기·수정·삭제가 표시된다. 키보드 도움말에서 답변 재생성을 확인했다. 최신 답변의 재생성 아이콘은 [11월 3일 관찰 기록](../../research/chat-ux-observation-2026-11-03.md)에 있다. | 캐릭터 답변 마지막 문단 바로 아래에 `리롤`과 `분기`를 배치하고 각각의 확인 화면을 만든다. 리롤은 같은 입력에 새 답변을 받는 동작, 분기는 이 답변까지를 새 방에서 이어가는 동작이다. |
| 설정의 유저 노트, 방·모드별 답변 길이/생각 조절, 요약 메모리의 장기·단기·관계도·목표 진입을 확인했다. | 모바일은 하단 시트, PC는 320px 우측 패널. 유저 노트·답변 길이·요약 메모리 상세 화면을 제공한다. 요약 메모리는 최근 요약과 장기 기억을 먼저 보여준다. |

단축어 항목 선택, 메시지 전송, 리롤, 분기, 설정 적용을 크랙에서 실행하지 않았다. 패널이 넣은 슬래시는 제거하고 설정 패널을 처음 상태로 돌렸다. 단축어의 실제 삽입 형식, 리롤 비용과 후보 관리, 분기 시 이관 범위는 직접 확인하지 못했다. 별표의 정확한 해석 규칙은 크랙에서 입력·전송으로 검증하지 않았다. 아래 문법은 이번 피드백에 따른 모서리의 설계 규칙이다.

## 작성과 답변 액션

- 저장 안내 문구는 네 대표 화면과 추가 시안에서 제거했다. 초안 저장 동작은 유지하되 화면에 상시 문구를 두지 않는다.
- `**` 버튼은 선택한 글을 `**묘사**`로 감싼다. 선택이 없으면 시작·끝 표식을 넣고 커서를 사이에 둔다. `**` 안은 묘사, 바깥은 대사로 처리한다. 닫히지 않은 표식은 묘사로 강제하지 않는다. 한국어 조합 중에는 선택과 커서를 깨뜨리지 않는다.
- `/` 단축어는 다음 답변에만 적용한다. 시안에서 프롬프트 원문 대신 칩의 이름과 제거 버튼을 보여준다. 칩을 선택하거나 제거하는 것만으로 전송하지 않는다. 실제 연동 시에는 허용된 단축어 ID와 입력 본문을 구분하고, 명시적 전송 뒤에 서버가 권한과 버전을 확인해 확장한다. 단독 실행 가능한 유틸과 대사를 보조하는 단축어를 구분한다.
- 기존 로어 진입은 `+`로 유지한다. 로어 선택, `**` 묘사, `/` 단축어를 서로 다른 동작으로 제공한다.
- 리롤·분기의 확인 화면은 답변을 읽는 위치에서 접근한다. 과거 답변의 리롤을 허용할 경우 후속 이력을 덮어쓰지 않는 규칙이 먼저 필요하다. 지원되지 않는 답변·상태의 액션은 제품에서 노출하지 않는다. 생성 실패 재시도는 리롤과 구별한다.

## 검수와 연결 범위

네 대표 화면에 단축키와 메시지 액션을 반영하고 저장 안내가 0개인지 확인했다. 390px 작성 도구, 단축어 목록, 적용 칩, 라이트 하단 시트, 1440px 다크 패널과 유저 노트·길이·메모리 상세 화면을 렌더링해 검사했다. 주요 화면은 편집 가능한 Figma 텍스트·벡터·컴포넌트이며, 화면 전체를 이미지로 붙이지 않았다.

Figma는 예시 초안·단축어 선택과 제거·리롤/분기 확인·설정 상세 이동을 연결한다. 실제 IME 입력, 생성, 과금, 저장을 실행하지 않는다. 빈 작성란에서도 완전히 별개의 예시로 이어지는 추가 시연 경로는 Figma Starter 호출 한도로 반영하지 못했다. 실제 제품에서는 목록을 열거나 단축어를 골라도 기존 초안이 변하지 않아야 한다.

공개 답변 요청은 기존 사용자 메시지 ID·revision·대상 캐릭터·수동 로어 ID를 받는다. 단축어 ID, 방별 출력량과 생각 깊이, 유저 노트, 성공 답변의 후보 생성, 새 방 분기의 계약은 현재 조사 범위에서 확인되지 않았다. 메시지 교체·되돌리기 API는 리롤 후보 보존이나 원본 방을 유지하는 분기의 대체 계약이 아니다. 메모리 내부 요약 기능과 사용자에게 보여주는 조회 계약도 구분한다.
