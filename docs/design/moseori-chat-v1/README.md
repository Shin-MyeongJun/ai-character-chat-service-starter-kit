## 이번 검토 범위

모바일·PC와 Light·Dark의 네 화면, 스크롤 가능한 실제 1,068자 답변, 공통 헤더·입력창·사용자 메시지·캐릭터 답변·아이콘 제어·최신 이동 요소. 모두 편집 가능한 Figma 레이어와 컴포넌트 인스턴스다. 완성 화면을 이미지로 붙이지 않았다.

본문 세로 스크롤과 ‘최신 메시지로’의 SCROLL_TO 연결을 설정했다. 연결 구조는 검사했으나 Figma Present에서 직접 클릭한 실사용 검증은 아직 하지 않았다. 설정 열기·자유 입력·전송의 전체 프로토타입은 다음 단계 범위다. 작성란은 빈 상태를 표현하며, 눌러 실제 입력되는 제품 구현은 아니다.

키보드 열린 화면, 설정 시트·패널, 로딩·새 대화·여러 왕복, 생성 대기·확정 실패·요청 결과 확인·크레딧 부족·초안 복원·새 답변 알림은 대표 시안 리뷰 후 확장한다.

## 시각 기준과 관찰 근거

참고 파일 [Studio Admin · 관리자 조회 v1](https://www.figma.com/design/yVzKbeu9mNhbXrZhGBkuqO)은 읽기 전용으로 조사했다. 실제 `5:921` 상세 화면 스크린샷과 텍스트·변수 바인딩을 확인했다. Noto Sans KR Regular/Medium/Bold, 얇은 경계선, 8/12px 모서리, 4/8/12/16/24/32px 여백 체계를 계승했다. 원본은 변경하지 않았다.

관리자 컴포넌트와 변수의 키 가져오기는 ‘not found’로 실패했다. 공개 SDS의 AI Chat 예시도 확인했지만 일반 챗봇의 헤더·푸터·레이아웃으로, 캐릭터의 긴 문단과 기존 관리자 타이포를 대신하기에는 부적합했다. 새 파일에 필요한 구성 요소만 만들었다. 저장소에 Code Connect 파일은 없었다.

색상은 Studio의 중성 팔레트를 계승했다. Light의 canvas #FFF, 본문 #202024, 보조 #65656F, 경계 #E5E5E8. Dark는 canvas #1C1C1E, 본문 #F4F4F5, 보조 #B2B2BB, 경계 #3D3D42. Starter의 단일 모드 제약을 고려해 Light·Dark 의미 색상 컬렉션을 분리하고 공통 primitive에 alias했다.

크랙은 [2026-11-03 기존 실화면 관찰 기록](../../research/chat-ux-observation-2026-11-03.md)을 근거로 사용했다. 입력 옆 보조 메뉴와 접히는 헤더 설정 패널은 직접 관찰 기록에 있다. 대화 문구·사적 내용·캐릭터·계정 정보는 가져오지 않았다. 예시 ‘에린’과 기록실의 대화는 모서리의 가상 예시다. 이번 작업 중 크랙의 현재 채팅방을 새로 관찰한 것은 아니다.

크랙의 실제 모바일 키보드, 읽기 위치 유지, 새 답변 도착 처리, IME 전송, 실패·복구·과금은 직접 검증되지 않았다. 아래 내용은 모서리의 설계 가정과 구현 제안이며 경쟁 서비스의 관찰 사실이 아니다.

## 읽기와 작성 규칙

| 항목 | 제안 |
| --- | --- |
| 모바일 본문 | 390px 화면 / 좌우 24px / 본문 342px |
| PC 본문 | 1440px 화면 / 중앙 최대 680px |
| 서술 | Noto Sans KR Regular 16px / 29px / 보조 명도 |
| 대사 | Medium 16px / 28px / 기본 본문 명도 |
| 문단 사이 | 16px, 메시지 그룹 사이 24px |
| 사용자 메시지 | 우측 정렬 / 270px / 14px·22px / 중성 바탕 |
| 헤더 | 모바일 56px / PC 72px, 작품·캐릭터 각각 1줄 말줄임 |
| 입력 제어 | 44×44px 클릭 영역 / 입력 영역 12px 모서리 |
| 초안 | 작성란 아래 자동 저장 안내. 실제 복원 성공시에만 복원 알림 |

서술과 대사의 시각 구분은 예시 콘텐츠에 명시한 블록 역할을 기반으로 한다. 현재 서버의 평문 문자열에서 인용부호를 임의 해석해 실제 역할을 확정한 것은 아니다. 구현 시 블록 문법·안전한 렌더러 계약을 결정해야 한다. 별표 입력을 서버가 보장된 문법으로 처리한다고 안내하지 않는다.

다음 단계에서 입력창은 1~5줄까지 내용에 따라 자라고 그 이후 내부 스크롤한다. 모바일은 visual viewport의 남은 높이에 붙이고 키보드가 없을 때 `env(safe-area-inset-bottom)`을 적용한다. 현재 프레임은 모바일 하단 34px 여백을 가정한 디자인이며 실제 기기 검증은 별도다.

PC Enter 전송, Shift+Enter 줄바꿈. `compositionstart`~`compositionend`, `nativeEvent.isComposing`, 호환용 keyCode 229 동안 Enter 전송을 차단하고 조합 확정에만 사용한다. 모바일 Enter는 기본 줄바꿈, 전송은 버튼을 사용한다. 조합 종료 직후 같은 Enter 이벤트의 중복 처리도 방지한다. 빈 입력·불러오기·진행 중이거나 결과 불확정인 요청이 있을 때 전송 비활성. 현재 프런트는 isComposing 검사만 존재한다.

이전 글을 읽는 동안 새 답변이 와도 자동 이동하지 않는다. 화면의 첫 가시 메시지 ID와 상대 오프셋을 앵커로 보존하고, 별도의 ‘새 답변이 도착했어요’ 표시와 최신 이동 버튼을 제공한다. 바닥에 머물던 경우에만 최신 위치를 따라간다. 위쪽 이력을 추가할 때도 앵커를 복원한다. 설정을 닫거나 글자 크기를 바꿔도 앵커와 초안을 보존한다. 현 대표 화면의 최신 이동 버튼은 아래에 이어지는 긴 답변으로 이동하는 읽기 탐색 예시다.

설정은 모바일 하단 시트(최대 화면 높이 70%, 내부 스크롤), PC 우측 320px 패널을 제안한다. 뒤 대화의 일부를 유지하고 글자 크기 14/16/18/20px, 행간 1.6/1.8/2.0, Light/Dark/기기 설정, 대화 정보를 제공한다. 색상만으로 선택 상태를 표현하지 않는다. 시트를 닫으면 설정 버튼으로 포커스를 복원한다.

## 현재 코드 계약과 후속 상태

`apps/web/app/chats/[id]/page.tsx`, `apps/web/lib/api.ts`, chat 모듈의 answers router·schemas·architecture를 조회했다.

- **전송:** 사용자 메시지 저장과 답변 요청은 별개이며 `messageKey`·`answerKey`를 별도로 보존한다. 작성 내용을 pending에 보존한 뒤 작성란을 비운다. 미확정 요청이 있으면 새로운 전송을 차단한다.
- **대기:** pending 응답은 같은 answer key로 확인한다. 토큰 스트리밍·실제 진행률·생성 취소를 보장하는 계약으로 해석하지 않는다. ‘답변을 기다리고 있어요’와 상태 확인 흐름으로 확장한다.
- **연결 단절·저장 복구:** `storage_pending_recovery`와 네트워크 오류는 결과 불확정이다. ‘기존 요청 결과 확인’을 표시하고 같은 key를 사용한다. 새 답변을 생성하는 재시도로 바로 바꾸지 않는다. 대기 중단은 공급자 생성 취소가 아니다.
- **확정 실패:** 서버가 종료 실패와 `retryable`을 반환한 경우만 사용자 메시지 옆에 ‘답변 다시 시도’를 둔다. 저장된 사용자 메시지는 재전송하지 않고 새 answer key를 사용한다. 재과금·환급을 임의 확약하지 않는다.
- **초안:** 실제 대화는 사용자 ID·방 ID별 localStorage, pending은 같은 범위의 sessionStorage다. 다른 계정·방의 초안이나 요청을 복원하지 않는다. 같은 기기의 초안 복원과 다른 기기 동기화를 구분한다.
- **크레딧:** 402는 부족 안내로 분리한다. 알고 있는 잔액·서버 가격만 표시하고 값이 없으면 추정 금액을 만들지 않는다. 작성 내용을 유지하며 기존 결과 조회를 새 유료 생성과 혼동하지 않게 한다.
- **수동 로어:** 발행 스냅샷의 허용 ID를 `manual_entry_ids`로 이번 답변에 한정해 전달하는 계약이 있다. 입력 옆 + 메뉴에서 접근시키고 진행 중에는 선택을 잠근다.
- **성공 답변 재생성·편집·분기:** 조사한 공개 계약에서 지원을 확인하지 못했다. 대표 화면에는 노출하지 않는다. 종료 실패의 재시도와 구별한다.

읽기 위치 유지·새 답변 표시, 모바일 Enter 정책, auto-grow·viewport 대응은 이번 설계 제안이다. 기존 프런트에 이미 모두 구현되어 있다고 보지 않는다.

## 검수 및 파일

네 화면을 실제 렌더링해 사용자 말풍선·캐릭터 이름·입력 도구의 높이 수축을 수정했다. 최종 프레임의 읽기 열 342/680px, 본문 폰트 Noto Sans KR, 이미지 채움 0개를 확인했다. 긴 답변의 화면 밖 부분은 의도적인 내부 스크롤 콘텐츠다. Figma 상태 ledger는 `figma-state.json`, 가상 대화는 `content.json`, 제작 소스는 같은 폴더의 JS다. JS는 제작 기록이며 재실행하면 중복 생성되므로 자동 실행하지 않는다. 후속 보정은 실제 Figma·상태 기록을 기준으로 한다.

백엔드 및 제품 동작을 바꾸지 않아 품질 스크립트·업무 테스트는 실행하지 않았다. 기존 작업 트리의 다른 문서 변경은 건드리지 않았다.
