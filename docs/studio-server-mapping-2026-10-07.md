# 스튜디오 → 서버 매핑 및 현재 범위

| 스튜디오 값 | 서버 저장·발행 |
| --- | --- |
| 제목·소개·공개 범위·기본 시작 장면 | 소유자 전용 `PUT /products/{id}/studio-draft`에 v2 문서와 revision 저장. 첫 발행 전에는 상품 profile도 갱신하며, 발행 이후에는 명시적 후속 발행에서만 반영. |
| 캐릭터 이름·소개·성격·대사·관계 | 첫 발행 시 character 원본 생성. 성격·대사·관계를 `persona_prompt`로 합치고 소개를 description에 저장. |
| 세계 규칙·로어 항목 | 첫 발행 시 하나의 로어북에 `rule` 및 종류별 항목으로 저장. 후속 발행은 기존 ID로 제목·설명·항목·태그를 동기화하며 이전 스냅샷은 보존. 활성화·키워드·우선순위·토큰 예산을 변환. |
| 시작 장면 | 같은 로어북의 `start_set` 항목으로 저장하고 `start_entry_ids`에 연결. 기본 장면 opening을 상품 opening_message에 저장. |
| 참여자·모델·발행 안내 | 대표 캐릭터, 구성, 모델·추론 수준, 첫 릴리스를 `/products/{id}/studio-publication`에서 한 트랜잭션으로 생성. |
| 이미지 | 브라우저 IndexedDB에만 원본이 있다. 서버 저장·가져오기 화면은 다른 기기에서 누락된 원본을 알린다. 이미지가 포함된 작품은 발행 전에 차단한다. 서버 업로드·스냅샷 연결은 남은 작업이다. |

브라우저 작품 ID와 서버 상품 UUID 연결은 사용자별 로컬 저장소에 보존한다. 첫 요청 전에 UUID를 기록하므로 저장 응답이 유실되어도 같은 상품에 재시도한다. 서버는 문서 digest가 같으면 revision을 올리지 않고, 다른 기기에서 바뀐 문서는 브라우저가 덮어쓰지 않는다. 서버 초안 가져오기는 `/products/mine`과 각 상품의 스튜디오 문서를 읽어 현재 브라우저에 없는 작품만 합친다. 같은 ID의 서로 다른 로컬 편집본은 보존하고 알린다.

2026-10-29 발행 계약 정정: 발행 후 변경 저장과 후속 버전 발행을 허용한다. 초안 저장만으로 현재 상품의 제목·공개 범위·태그·승인 상태를 바꾸지 않으며 명시적 발행에서 반영한다. 서버 구성 ID와 과거 스냅샷을 보존하고 revision별 발행 영수증으로 응답 유실 재시도를 복구한다. revision 충돌과 같은 revision의 다른 발행 요청 파라미터는 409다(legacy 영수증은 기존 복구 경로 유지). 공개 목록은 관리자 승인된 public 상품만 포함한다. 실제 브라우저·PostgreSQL·LLM 통합 검증은 별도이며 위 이미지 행은 초기 범위 기록이다.
