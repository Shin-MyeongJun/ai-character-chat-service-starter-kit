# 제작 스튜디오 작업실·편집 범위 수정

2026-10-06. 사용자 확인 항목 7개를 수정했다. 백엔드/API/실제 AI 실행은 변경하지 않았다.

## 화면 동작

- `/studio` 최초 진입은 내 작업실이다. 작품·캐릭터·로어북·휴지통 보관함을 표시한다. 특정 작품의 자료 탐색기, 미리보기, 테스트·발행 버튼은 작품 진입 전 렌더링하지 않는다.
- 새 작품은 빈 초안이다. 여러 작품을 생성하고 목록에서 선택한다. 각각 독립된 제목·내용·자료·장면을 저장한다.
- 작품·캐릭터·로어북마다 이름/제목/태그 검색과 초기화를 제공한다. 검색어를 각각 보존한다. 작품 내부 자료 검색은 보관함 검색과 별도 상태다.
- 보관함 캐릭터와 로어는 독립 원본이다. 보관함에서 열면 `원본 편집` 안내와 실제 원본 저장이 일치한다.
- 작품 내부 편집은 `이 작품에서만 적용`이다. 원본 연결 시 새 ID를 가진 깊은 복사본을 만들고 `sourceId`로 출처를 남긴다. 이미지 파일 ID는 재사용하여 기존 파일 연결을 보존한다.
- 원본을 수정해도 기존 작품 복사본을 자동 갱신하지 않는다. 이후 새로 연결하는 작품에는 현재 원본 값을 복사한다. 연결 창과 편집 화면에 이 동작을 설명한다.
- 출처를 알 수 없는 기존 캐릭터·로어를 독립 원본으로 승격하지 않는다. 기존 작품에서만 편집할 수 있게 보존한다.
- 첫 인물은 `내레이션 · 인물 선택 안 함`을 선택할 수 있다. 캐릭터가 없어도 장면과 미리보기를 유지한다. 장면이 없는 새 작품도 정상적으로 열린다.
- 화이트/다크 토큰과 모바일 자료·편집·미리보기 전환을 유지한다. 작업실에는 작품 전용 모바일 탐색도 표시하지 않는다.

## 제거와 복구

| 대상 | 동작 | 복구 |
|---|---|---|
| 작품 | 작품 전체를 휴지통으로 이동; 독립 원본 유지 | 작품 전체 복구 |
| 독립 원본 | 원본을 휴지통으로 이동; 기존 작품 복사본은 내용을 유지하고 작품 전용으로 전환 | 원본 복구; 해제된 출처 연결은 자동 재연결하지 않음 |
| 작품 캐릭터 | 해당 작품에서 해제; 이를 참조한 장면 인물 선택 비움 | 자료 복구, 기존 참조 장면의 선택이 여전히 비어 있으면 재연결 |
| 작품 로어 | 해당 작품에서 해제; 장소 참조 비움 | 자료 복구, 기존 참조 장면의 선택이 여전히 비어 있으면 재연결 |
| 시작 장면 | 장면을 휴지통으로 이동; 기본 장면이면 남은 첫 장면 또는 빈 선택으로 변경 | 장면 복구; 없는 인물/장소 참조는 비움 |

확인 창은 영향 범위와 취소·휴지통 이동 버튼을 제공한다. 영구 삭제 기능은 제공하지 않는다. 소속 작품이 삭제된 자료는 해당 작품을 먼저 복구해야 한다. 삭제 자료의 이미지 파일은 복구를 위해 IndexedDB에 유지한다.

삭제 이후 다른 편집을 진행해도 복구가 전체 작품을 과거 상태로 되돌리지 않는다. 복구 항목과 안전하게 복원할 수 있는 참조만 추가한다.

## 저장 이전

- 새 키: `chat-kit-studio-workspace-v3`.
- v3가 있으면 v3를 우선한다. v3가 없을 때만 기존 `chat-kit-studio-draft-v2` 또는 v1을 이전한다.
- 이전 v1/v2 키는 수정하지 않는다. 내용·ID·태그·고급 로어 값·장면 연결·이미지 ID를 보존한다.
- 읽을 수 없는 v3는 시간별 백업 저장이 성공한 뒤에만 새 값을 저장한다. 실패 시 저장을 진행하지 않는다. 읽을 수 없는 이전 키도 보존한다.
- 저장 값의 타입, 중복 ID, 수치 범위, 장면과 원본 참조, 휴지통 구조를 검사한다.
- 다른 탭이 저장한 변경은 미편집 탭에 동기화한다. 미저장 편집과 충돌하면 새 값을 덮어쓰지 않고 내보내기·새로고침을 안내한다. 삭제된 자료를 다른 탭에서 보고 있었다면 작업실/작품 개요로 이동한다.

## 검증

TypeScript 검사, Next.js 프로덕션 빌드 및 초안/미리보기/작업실 자동 테스트 14개가 통과했다.

실제 인앱 브라우저에서 다음을 확인했다.

1. 작업실에는 작품 사이드바·미리보기·테스트·발행이 없다.
2. 기존 CHARX 초안이 이전됐다. 작업 시작 당시 캐릭터 **4개**, 로어 **8개**, 장면 **2개**였으며 최종 정리 후 동일 수량과 제목·소개가 유지됐다. 사용자 추가 캐릭터도 보존했다.
3. 빈 작품 A/B를 만들고 각각 독립 저장했다. A에 원본 캐릭터·장소와 장면을 연결했다.
4. A의 캐릭터 성격을 바꿔도 원본은 v1을 유지했다. 원본을 v2로 바꾼 뒤 B에 연결하면 B는 v2, A는 A의 수정값을 유지했다. A의 로어 본문 수정도 원본의 v1 본문에 영향을 주지 않았다.
5. 작품·캐릭터·로어 검색 결과가 동작하고, 탭마다 입력값이 독립 유지됐다. 작품 내부 검색을 바꿔도 보관함 입력은 유지됐다.
6. 연결 해제 취소 시 자료 유지. 캐릭터 해제 후 장면 인물 선택 비움, 복구 후 다시 연결됨. 로어 해제 후 장소 비움과 복구 확인.
7. 마지막 장면 삭제 후 빈 미리보기·비활성 테스트가 정상. 휴지통에서 장면 복구 확인.
8. 원본 삭제의 영향 안내가 연결 작품 2개를 표시했다. 삭제 후 A의 수정된 복사본과 장면은 유지됐다. 원본 복구와 작품 B 삭제·복구도 확인했다.
9. 새로고침 및 새 탭에서 기존 CHARX와 작품 A/B를 다시 불러왔다. 다른 탭에서도 최종 삭제·휴지통 수량이 동기화됐다.
10. 390×844 모바일에서 화이트·다크 작업실, 자료 탐색, 장면 편집, 미리보기/테스트 전환을 확인했다. 미리보기의 가로 넘침이 없었다. 데스크톱 테마 확인 후 라이트 모드와 기본 뷰포트로 복귀했다.
11. 브라우저 오류·경고 로그가 없었다.

검증용 작품 A/B와 독립 원본 2개는 **휴지통에 보관**했다. 원래 CHARX 작품은 활성 목록에 남겼다. 화면 캡처는 `tmp/studio-workspace-review/`에 있다.

## 남은 범위

서버 저장·발행·AI 실행·CHARX 자동 가져오기는 미연결이다. 현재 독립 로어 보관함은 기존 편집기의 로어 항목 단위로 관리한다. 원본 변경을 이미 연결된 작품에 반영하는 동기화/병합 기능은 제공하지 않는다. 이미지 파일은 같은 브라우저의 IndexedDB에 보관되며 작업실 JSON은 파일 목록만 포함한다. 여러 탭에서 동시에 미저장 편집을 하는 경우 자동 병합 대신 충돌을 안내한다.
