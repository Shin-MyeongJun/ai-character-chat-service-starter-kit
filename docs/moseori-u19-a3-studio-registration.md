# 모서리 U19 a3 스튜디오 이미지 등록

기준은 `codex/u19-a2`의 `55fb9e7`이다. 별도 a3 워크트리로 기존 UI 초안을 복사해 일반 작품 편집기에 연결했다. 개발용 `/dev/studio-images`에서도 a1 예시를 편집할 수 있다.

캐릭터에는 표정과 상황을, 로어북에는 상황을 등록한다. 추가는 새 수집 항목 UUID를 만들고 교체는 같은 수집 항목에 새 작품 파일 버전을 연결한다. 같은 태그는 여러 항목에서 쓸 수 있다. 첫 장면은 0을 본문 앞, 양수를 해당 문단 뒤로 해석하며 같은 위치의 배치는 배열 순서를 따른다. 삭제된 이미지의 배치와 범위를 벗어난 문단 위치는 화면에서 표시하고 서버에서도 거절한다.

기존 작품 초안은 모든 대기 업로드가 완료된 뒤 한 번의 revision CAS로 갱신한다. 새 작품은 업로드 대상 작품 ID를 확보하기 위해 이미지 없는 초기 초안을 먼저 저장한다. 브라우저는 파일과 요청 UUID를 유지하고 성공한 파일 버전은 작품·계정·요청별로 기록한다. 업로드 응답 유실은 같은 키로 재시도하고, CAS 응답 유실은 서버 초안과 해소된 문서를 비교해 복구한다. 저장 충돌에서는 서버 초안과 로컬 편집 및 완료된 업로드 결과가 보존된다.

## 실제 초안 예시

격리된 PostgreSQL 테스트의 `GET /products/{product_id}/studio-draft` 응답에서 a4 관련 필드를 발췌했다. 파일 버전 UUID는 실제 a2 업로드에서 발급받았다.

```json
{
  "product_id": "273b4acb-0c20-4766-b715-5c124ddf60ae",
  "revision": 2,
  "document": {
    "version": 2,
    "chatImageItems": [
      {
        "imageItemId": "20000000-0000-4000-8000-000000000002",
        "fileVersionId": "16a54e6a-7cc5-4905-855f-af9223c18075",
        "target": {"kind": "lore_entry", "id": "workshop"},
        "kind": "situation",
        "tags": ["수리점"],
        "alt": "등불이 켜진 수리점"
      }
    ],
    "scenes": [
      {
        "id": "arrival",
        "opening": "수리점 문이 열렸다.",
        "openingImagePlacements": [
          {"imageItemId": "20000000-0000-4000-8000-000000000002", "afterParagraph": 1}
        ]
      }
    ]
  }
}
```

a4는 잠긴 revision의 `chatImageItems`, `scenes[].opening`, `scenes[].openingImagePlacements`를 읽는다. 필드가 누락된 구형 초안에서는 빈 목록으로 읽는다. 대상은 문서 로컬 ID이며 발행 시 기존 캐릭터·로어·장면 매핑을 사용한다. 파일 버전이 null 또는 비가용이면 발행을 거절한다. 스냅샷의 항목과 순서 있는 시작 블록을 동결하고 a2의 `snapshot` 참조를 같은 발행 트랜잭션에 기록하는 것이 a4의 연결 지점이다. 이미지가 있는 작품의 발행은 이 동결 경로가 연결될 때 활성화한다.

## 검증

- 프로젝트 가상환경의 `tools/check_backend_quality.py` 및 `pnpm web:typecheck`.
- PostgreSQL에서 CAS 충돌, 같은 파일의 다중 사용, 마지막 사용처 해제, 다른 작품 파일 거절, 실패 시 참조 롤백, 삭제한 항목 ID 재사용 거절을 검증했다.
- 실제 a2 HTTP 업로드와 스튜디오 HTTP 저장 경로를 묶어 부분 실패, 같은 키 재호출, 저장 응답 재호출, 별도 HTTP 클라이언트의 초안 복원과 소유자 미리보기를 검증했다. 웹 테스트는 전송을 대체해 응답 유실과 브라우저 저장소를 통한 재시도를 재현했다.
- 브라우저와 실제 API를 한 번에 연결한 수동 검증, a4 발행 동결·재발행·스냅샷 보존 검증이 남아 있다.
